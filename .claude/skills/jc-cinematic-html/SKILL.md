# JC Cinematic HTML — 시네마틱 캠페인 룩 빌드 엔진

HTML 산출물에 **"지금 촬영 중인 프리미엄 광고"** 룩을 재현하는 전용 스킬이다. 웜 블랙 스테이지 + 단일 오렌지 광원 + 미니어처 디오라마 시네마틱 포토(히어로) + 필름 레코딩 크롬(뷰파인더·REC—LIVE·러닝 타임코드). 어둠이 기본값이고, 오렌지 빛은 화면당 하나만 허락된다.

> 본 스킬이 이 룩의 **정본(SoT)** 이다. `jc-design-system/references/cinematic-campaign-html.md`는 본 스킬로의 포인터다.

## 핵심 원칙

1. **파생 테마 지위** — jc-design-system 시그니처(딥네이비·일렉트릭블루)를 수정하지 않는다. 산출물 단위 `:root` 오버라이드 레이어로만 적용한다.
2. **스크린 전용** — 발표·웹 전용 룩. 인쇄/PDF 배포 산출물에는 `shared-rules.md#RULE-PRINT-LIGHT`(라이트 강제)가 우선한다.
3. **시각 라우팅** — 히어로 사진·영상 생성은 Higgsfield(`RULE-VISUAL-ROUTING`), 크롬·SVG·레이아웃은 Claude가 직접 그린다.
4. **식별정보 금지** — 클라이언트 실명·전용 컬러 하드코딩 금지(`RULE-NO-COMPANY`). 캠페인 액센트는 주입 변수다.
5. **모션 규율** — 영상 루핑 금지. 섹션 진입 시 1회 재생 → 마지막 프레임 정지 (2026-07-25 확정).

## 사용 시점

- **신규 빌드**: 시네마틱 룩의 발표덱·행사 랜딩·쇼케이스·대시보드를 처음부터 제작
- **리스킨**: 기존 HTML 산출물에 본 룩 이식 (콘텐츠·엔진 유지, 스킨 레이어 교체)
- 다른 스킬(mice-dashboard·jc-landing-page 등) 작업 중 사용자가 본 룩을 지정하면 해당 스킬의 산출 구조 위에 본 스킬의 스킨 절차를 적용

## 워크플로우

### A. 신규 빌드
1. `references/build-kit.md` §2 토큰 블록으로 `:root` 구성 → §3 레이어 아키텍처로 페이지 골격
2. §5 컴포넌트 규격(웜 글래스 카드·아이브로·STEP 띻벨·CTA·타입 스케일) 적용
3. §4 필름 크롬 스니펫 삽입 (뷰파인더·REC—LIVE·타임코드)
4. §7 파이프라인으로 디오라마 히어로 생성 (정지 컷 → 필요 시 모션) → WebP/base64 임베드
5. §6 모션 표준 적용 (1회 재생 옵저버 · CSP 환경은 Blob 로더)

### B. 리스킨 (기존 HTML)
1. §2 토큰 블록을 기존 CSS **최하단**에 삽입 (캐스케이드 승리)
2. **하드코딩 색 스캔** — `rgba(41,98,255` · `#2962FF` · `#5B9BD5` 등 토큰 밖 색상 전량 치환 (실측: 리스킨 1건에서 48건 발견 전례)
3. 크롬 삽입 → 히어로 슬롯 교체 → 모션 표준 전환
4. 검수: 잔존 쿨톤 0건 · 이미지 위 본문의 셰이드 확보 · 글로우 광원 화면당 1개

### C. 품질 게이트
- 대비: `#FF4A11` 위 흰 텍스트는 CTA·큰 텍스트 전용, 본문 금지 (`RULE-WCAG`, 검증은 jc-design-system `mode-mapping.md §9` 표준)
- 생성 이미지 육안 검수: 텍스트·로고 포함 컷 폐기
- "실물입니다" 류 신뢰 헤드라인 슬롯은 디오라마 대신 실제 캡처 교체 권장 주석
- 완성 산출물의 최종 감수는 jc-redteam
