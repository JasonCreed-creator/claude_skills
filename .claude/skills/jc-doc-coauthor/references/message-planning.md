# 메시지 기획 문서 — 행사명 · 슬로건 · 핵심 메시지

> 행사명·슬로건·태그라인·핵심 메시지를 **후보로 펼쳐 ★추천 + 근거 + 버린 안**으로 확정하는 절차. SKILL.md의 3단계(컨텍스트 수집 → 구조·정제 → 레드팀 검증)에 그대로 얹힌다. 발행 명의 기본은 리멤버 MICE비즈팀, 발주처·행사명은 주입 슬롯(`{{client_company}}`·`{{event_name}}`).

**다루지 않는 것** — 경쟁 구도·포지셔닝 전략 분석은 `jc-strategy-canvas`(본 문서는 그 결론을 한 문장으로 받아 쓴다). 색·서체·무드보드·레이아웃 같은 비주얼 결정은 하지 않는다: KV 규칙은 `jc-kv-guide`, 토큰 값은 `jc-design-system`, 이미지는 Higgsfield(`RULE-VISUAL-ROUTING`).

## 1. 흐름

```
Stage 1  §2 질문 세트에서 자료로 답이 안 되는 빈칸만 한 번에 묻는다
Stage 2  기획안 = 포지셔닝 한 문장 + 보이스 위치 → 1회 확인
         → 행사명·슬로건 후보 펼치기(§3, 대화로만) → ★추천 + 근거 + 버린 안을 문서에
Stage 3  jc-redteam Quick Strike (공격 포인트 정본: jc-redteam chaining-guide §jc-doc-coauthor)
```

- 발언·원문은 그대로 모으고 해석은 따로 적는다. 주최 측이 실제로 쓴 표현이 후보와 근거의 1차 재료다.
- "무엇"이 나오면 "그게 왜 중요한가요?"를 2~4번 붙여 근본 이유가 나올 때까지 내려간다(래더링). 일반론·모호한 답에는 구체 사례·숫자 하나를 청한다.

## 2. 질문 세트 (빈칸만)

### 2.1 존재 이유 · 포지셔닝
- 이 행사는 왜 존재하는가 — 홍보 문구가 아니라 주최 측의 근본 믿음
- 핵심 타깃은 누구인가(참가자·발주처·스폰서·연사를 구분해 각각)
- 이 행사가 없으면 타깃은 무엇으로 대신하나(대체 행사·자체 개최·불참)
- 대안과 무엇이 다른가 — 타깃이 가장 중시하는데 남이 못 주는 가치
- 주최 측이 평소 쓰는 설명 문구·비유(원문 그대로)

**산출** — Why 한 줄 + 포지셔닝 한 문장:
> [타깃]이 [상황]할 때, {{event_name}}은 [카테고리]로서 [유니크 가치]를 준다. [대안]과 달리 [차별점].

### 2.2 보이스 · 톤
- 좋아하는 카피 / 싫어하는 카피(출처 포함 — 무엇이 정확히 어긋났나)
- 늘 쓰는 말 / 적극 피하는 말
- 어디서 어떻게 들려야 하나: 초청장·모집 페이지 / 현장 사이니지 / 발주처 제안서 표지 / SNS
- "우리는 항상… / 우리는 절대…" 원칙

**산출** — 5축 위치(격식↔캐주얼 · 진지↔유쾌 · 거리감↔따뜻함 · 관습↔파격 · 절제↔표현, 각 1~5) + 보이스 문장 1단락 + 모든 후보가 통과할 **체크 3개**.

### 2.3 네이밍 제약
- 이름에 꼭 들어갈 것(주최명·연도·회차·도시) / 들어가면 안 될 것
- 국문·영문 병기, 약칭 필요 여부, 길이 한도(사이니지·URL·해시태그)
- 기존 행사명 승계인가 신규인가
- 상표·도메인·기존 행사명 충돌 확인은 누가 하나

### 2.4 슬로건 · 핵심 메시지 제약
- 쓰일 자리(KV 메인 카피·표지·오프닝 영상·굿즈)
- 매년 바뀌는 연도 슬로건인가, 고정 태그라인인가
- 참가자가 행사 후 한 문장으로 말하길 바라는 것(핵심 메시지)
- 트루라인 초안: "{{event_name}}은 [유니크 주장]을 하는 유일한 [카테고리]."

## 3. 후보 펼치기 → ★추천

**생성 규칙**
- 섹션 5스텝의 브레인스토밍 그대로: 행사명·슬로건 각각 **5~20안**, 번호 목록, 추천 조합에 ★. 목록은 대화로만 낸다.
- 방식을 섞는다 — 행사명: 서술형 · 조어 · 약어 · 은유 · 장소/연도형. 슬로건: 보이스 위치 ±1 범위에서 register 변주.
- 후보마다 리스크 태그: 발음 · 중의 · 부정 연상 · 상표/도메인 충돌 의심 · 영문 어색함 · 길이 초과.

**거르는 기준** — 보이스 체크 3개에 더해:
- 포지셔닝 한 문장과 이어지는가(차별점이 이름·슬로건에서 읽히는가)
- 대안 행사 이름과 혼동되지 않는가
- 사이니지·URL·해시태그로 실제 쓸 수 있는가
- 근거 없는 최상급("최고·최대·유일·최초")은 슬로건에서도 쓰지 않는다. 근거가 있으면 출처를 각주로

**문서에 남기는 것** — 확정 본문만: ★추천 1안 + 예비 1안 + 근거 + 리스크, 버린 안 3~5개는 사유 한 줄씩.

## 5. 하류 연결

- **jc-kv-guide** — KV 가이드 §5 무드·톤 키워드는 원문 인용만 허용하므로, 이 문서의 *확정 본문*(보이스 문장·핵심 메시지)이 인용 출처(D-번호)가 된다. 확정 전 후보 목록은 넘기지 않는다.

## 6. 반례

| 압박 패턴 | 올바른 대응 |
|-----------|-------------|
| "후보만 30개 뽑아줘, 고르는 건 내가" | 늘려도 되지만 ★추천·근거·리스크 태그는 붙인다. 목록만 주면 결정 비용이 그대로 사용자에게 돌아간다 |
| "슬로건에 '국내 최대' 넣어줘" | 출처·수치가 있으면 각주와 함께, 없으면 버린 안으로 보내고 사유를 적는다 |
| "이름 정하는 김에 KV 컬러·무드도 잡아줘" | 하지 않는다. KV 규칙 문서는 `jc-kv-guide`(브랜드 가이드 원문만), 값은 `jc-design-system` |
| "경쟁 행사 대비 포지셔닝 분석부터 해줘" | 분석은 `jc-strategy-canvas`. 그 결론을 §2.1 포지셔닝 한 문장으로 받아 이어간다 |
| "상표 검색은 됐다 치고 확정으로" | 확인 필요 목록에 남긴다. 확정 표기는 사용자가 확인한 뒤에만 |
