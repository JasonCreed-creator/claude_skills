## 1. 행사 기획서

**용도**: 행사의 목적·콘셉트·구성을 정리해 내부 합의 또는 발주처 제안의 토대를 만든다. (발주처에 *보여줄* 슬라이드는 jc-pptx로 변환.)

**섹션 골격**:
1. 행사 개요 (목적·일시·장소·규모 — 1p 요약)
2. 배경·필요성 (왜 지금 이 행사인가)
3. 핵심 콘셉트·주제 *(미지의 것 최다 → 먼저 작성)* — 행사명·슬로건까지 정해야 하면 §6 메시지 기획 문서로 분리
4. 프로그램 구성 (세션·연사·콘텐츠 흐름)
5. 타깃·홍보 (참가자 정의 + 모객 전략)
6. 추진 체계·일정 (조직 R&R + 마일스톤)
7. 예산 개요 (상세 견적은 mice-estimate)
8. 기대효과·성공지표(KPI)

## 2. 운영계획서

**용도**: 확정된 행사를 *실제로 굴리는* 실행 계획. 현장 R&R·타임라인·리스크 대응이 핵심.

**언제 본 스킬로**: "같이 쓰자"·"섹션별로 묻고 가자" 신호가 있을 때만. "운영계획서 써줘·바로 내줘"는 `mice-ops-docs`가 직접 만든다.

**골격·입력 매핑·표 양식·마감 점검 (정본)**: `mice-ops-docs/references/ops-plan.md` §1~4. 본 스킬은 그 7섹션을 그대로 스캐폴드로 가져와 섹션별 5스텝으로 함께 채우기만 한다. 골격을 여기에 다시 적지 않는다(드리프트 방지).

**작성 순서**: 운영 조직·R&R(의사결정 라인)을 먼저, 운영 개요는 마지막 — ops-plan.md §2 순서를 따른다.

## 3. 전략 메모

**용도**: 하나의 권고/주장을 근거와 함께 설득하는 짧은 문서(보통 1~3p). 결론이 핵심.

**섹션 골격**:
1. 한 줄 결론 (TL;DR — 권고)
2. 맥락·문제 (왜 이 판단이 필요한가)
3. 핵심 논거 (2~3개, 근거와 함께)
4. 대안 비교 (검토하고 버린 것 + 버린 이유)
5. 리스크·반론 (Steelman — 가장 강한 반대)
6. 다음 단계 (동의 시 일어날 일)

검증 모드: 분량이 짧아 **Quick Strike** 권장.

## 4. 의사결정 문서 (Decision Doc)

**용도**: 단일 결정 질문에 대해 옵션·트레이드오프·권고를 제시해 결정권자가 *서명*하게 한다.

**섹션 골격**:
1. 결정 질문 (단일 질문 — 예/아니오 또는 A/B/C)
2. 배경·제약 (결정에 필요한 최소 맥락)
3. 옵션 + 트레이드오프 *(미지의 것 최다 → 먼저)*
4. 권고안 + 근거
5. 리스크·되돌릴 수 있는가(reversibility)
6. 결정 기한·결정권자·후속 조치

---

## 5. RFC (제안·설계 문서)

**용도**: 문제와 제안 접근을 정리해 리뷰·합의를 구하는 문서. (행사 운영 프로세스·시스템·정책 설계에 활용.)

**섹션 골격**:
1. 요약 (문제 + 제안 한 단락)
2. 문제·동기 (현재의 통점)
3. 제안 접근 *(핵심 → 먼저)*
4. 대안 + 기각 사유
5. 영향·의존성·롤백
6. 미해결 질문 (Open Questions)
7. 리뷰어·승인 경로

---

## 6. 메시지 기획 문서 (행사명·슬로건)

**용도**: 행사명·슬로건·태그라인·핵심 메시지를 후보로 펼쳐 **★추천 + 근거 + 버린 안**으로 확정한다. 확정본은 `jc-kv-guide`(KV 제작 가이드의 무드·톤 원문 출처)·`jc-pptx`(표지 카피·원 메시지)의 입력이 된다.

**섹션 골격** (질문 세트·후보 생성 규칙·양식 상세는 `message-planning.md`):
1. 메시지 과제 (무엇을 정하나 + 표기·길이·승계 제약)
2. 근거 — Why 한 줄 · 포지셔닝 한 문장 · 보이스 위치 *(미지의 것 최다 → 먼저)*
3. 행사명 — ★추천 + 예비 1안 + 근거·리스크 + 버린 안
4. 슬로건·태그라인 — 같은 구조
5. 핵심 메시지 (한 문장 + 지지 메시지 3)
6. 사용 규칙 (국문·영문·약칭 표기, 채널별 톤 한 줄 예)
7. 확인 필요 (상표·도메인 검색, 발주처 승인)

검증 모드: ★추천안 중심이라 **Quick Strike** 기본.

## 공통: 섹션 작성 순서 원칙

- **미지의 것이 가장 많은 섹션부터** 쓴다. 거기서 막히면 나머지가 흔들린다(의사결정=옵션/권고, RFC=설계안, 기획서=콘셉트, 메시지 기획=포지셔닝 한 문장).
- **요약·결론은 맨 마지막.** 본문이 굳은 뒤 써야 새 정보가 요약에 새지 않는다.
- **리스크·반론 섹션을 비워두지 않는다.** 이 섹션이 약하면 jc-redteam이 가장 먼저 친다(Steelman·숨은 가정).
- 모든 유형 공통으로 **회사·실명은 외부 주입 변수**(`RULE-NO-COMPANY`). 본문엔 "발주처"·`T社`·"본 사무국" 등 일반화 표현.
