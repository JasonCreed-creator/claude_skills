## 1. 행사 기획서

**용도**: 행사의 목적·콘셉트·구성을 정리해 내부 합의 또는 발주처 제안의 토대를 만든다. (발주처에 *보여줄* 슬라이드는 mice-proposal로 변환.)

**섹션 골격**:
1. 행사 개요 (목적·일시·장소·규모 — 1p 요약)
2. 배경·필요성 (왜 지금 이 행사인가)
3. 핵심 콘셉트·주제 *(미지의 것 최다 → 먼저 작성)*
4. 프로그램 구성 (세션·연사·콘텐츠 흐름)
5. 타깃·홍보 (참가자 정의 + 모객 전략)
6. 추진 체계·일정 (조직 R&R + 마일스톤)
7. 예산 개요 (상세 견적은 mice-estimate)
8. 기대효과·성공지표(KPI)

**jc-redteam 집중 공격** (차용: mice-proposal 공격 포인트):
- "콘셉트 → 기대효과" 인과 비약 — 이 콘셉트가 *왜* 그 효과를 낳는가
- 모객 가정의 낙관편향 — 기대 인원의 근거는 사실인가 희망인가
- 운영 리스크·예비비 누락 (화려한 기획 뒤 빈 곳)
- 숫자 일관성 — 인원/일정/예산이 서로 충돌하지 않는가
- 과장 표현 — 근거 없는 "최고/유일/최대"

## 2. 운영계획서

**용도**: 확정된 행사를 *실제로 굴리는* 실행 계획. 현장 R&R·타임라인·리스크 대응이 핵심.

**섹션 골격**:
1. 운영 개요 (행사 요약 + 운영 범위)
2. 운영 조직·R&R *(의사결정 라인 명확화 → 먼저)*
3. 상세 타임라인 (D-day 기준 임계 경로)
4. 구역·동선 계획 (등록·세션장·F&B·VIP)
5. 협력사·벤더 운영 (계약 상태 + 책임 경계)
6. 리스크·비상 대응 (시나리오별 대응 매트릭스)
7. 체크리스트 (사전/현장/철수)

**jc-redteam 집중 공격** (차용: 내용 검증 + 누락 관점):
- 책임자·기한 누락된 운영 항목 (회의록 Action 공격 포인트 차용)
- 임계 경로의 단일 실패점(SPOF)을 숨기지 않았는가
- 비상 시나리오의 *대응*이 실제로 실행 가능한가 (선언만 아닌가)
- 협력사 의존 항목의 계약·백업 공백
- 내부 모순 — 타임라인과 인력 배치가 충돌하지 않는가

## 3. 전략 메모

**용도**: 하나의 권고/주장을 근거와 함께 설득하는 짧은 문서(보통 1~3p). 결론이 핵심.

**섹션 골격**:
1. 한 줄 결론 (TL;DR — 권고)
2. 맥락·문제 (왜 이 판단이 필요한가)
3. 핵심 논거 (2~3개, 근거와 함께)
4. 대안 비교 (검토하고 버린 것 + 버린 이유)
5. 리스크·반론 (Steelman — 가장 강한 반대)
6. 다음 단계 (동의 시 일어날 일)

**jc-redteam 집중 공격** (차용: 내용 검증 + Steelman):
- 결론의 숨은 가정 — 이게 틀리면 권고가 무너지는 전제
- 논거의 사실/추정 구분 — 추정을 사실처럼 쓰지 않았는가
- 확증편향 — 결론에 유리한 근거만 모으지 않았는가
- 버린 대안을 허수아비로 세우지 않았는가 (기각 전 강화 위반)
- **Quick Strike 권장** (짧은 분량) — 인라인 비평으로 빠르게

## 4. 의사결정 문서 (Decision Doc)

**용도**: 단일 결정 질문에 대해 옵션·트레이드오프·권고를 제시해 결정권자가 *서명*하게 한다.

**섹션 골격**:
1. 결정 질문 (단일 질문 — 예/아니오 또는 A/B/C)
2. 배경·제약 (결정에 필요한 최소 맥락)
3. 옵션 + 트레이드오프 *(미지의 것 최다 → 먼저)*
4. 권고안 + 근거
5. 리스크·되돌릴 수 있는가(reversibility)
6. 결정 기한·결정권자·후속 조치

**jc-redteam 집중 공격** (차용: mice-rfp GO/NO-GO 판정 공격 포인트):
- 권고의 **숨은 가정** — 결론을 떠받치는 미검증 전제
- 낙관편향 — 권고안의 성공 확률을 부풀리지 않았는가
- 매몰비용·현상유지 편향 — 익숙한 선택을 합리화하지 않았는가
- 옵션의 트레이드오프를 *진짜* 적었는가 (불리한 면 은폐 여부)
- 되돌릴 수 없는 결정인데 reversible로 오판하지 않았는가

## 5. 사후 결과보고 개요

**용도**: 행사 종료 후 성과·교훈을 보고하는 산문 개요. (수치 대시보드는 mice-dashboard로 별도 시각화.)

**섹션 골격**:
1. 핵심 요약 (목표 대비 실적 한눈에)
2. 성과 지표 (KPI 목표 vs 실적)
3. 잘된 것 (Keep)
4. 안 된 것·이슈 (Problem — 불리한 지표 포함)
5. 다음에 바꿀 것 (Try — 차기 개선)
6. 결론·차기 연결 (다음 의사결정으로)

**jc-redteam 집중 공격** (차용: mice-dashboard KPI 해석 공격 포인트):
- 인과 착각 — 상관을 성과 *요인*으로 단정하지 않았는가
- 사후확신 편향 — "예상대로"가 실제 사전 예측과 일치하는가
- 누락된 부정 지표 — 불리한 KPI를 숨기지 않았는가 (확증편향)
- 데이터 → 결론 비약 — 수치가 결론을 실제로 뒷받침하는가

## 6. RFC (제안·설계 문서)

**용도**: 문제와 제안 접근을 정리해 리뷰·합의를 구하는 문서. (행사 운영 프로세스·시스템·정책 설계에 활용.)

**섹션 골격**:
1. 요약 (문제 + 제안 한 단락)
2. 문제·동기 (현재의 통점)
3. 제안 접근 *(핵심 → 먼저)*
4. 대안 + 기각 사유
5. 영향·의존성·롤백
6. 미해결 질문 (Open Questions)
7. 리뷰어·승인 경로

**jc-redteam 집중 공격** (차용: 내용 검증 + 대안 제시):
- 제안 접근의 논리 비약 — 문제 → 해법 사이 인과
- 대안 기각 사유의 정당성 (성급한 기각 여부)
- 영향 범위 과소평가 — 의존성·부작용 누락
- Open Questions가 *실은 결론을 흔드는* 미결인지
- 더 나은 접근 제시 (Steelman 후 대안)

---

## 공통: 섹션 작성 순서 원칙

- **미지의 것이 가장 많은 섹션부터** 쓴다. 거기서 막히면 나머지가 흔들린다(의사결정=옵션/권고, RFC=설계안, 기획서=콘셉트).
- **요약·결론은 맨 마지막.** 본문이 굳은 뒤 써야 새 정보가 요약에 새지 않는다.
- **리스크·반론 섹션을 비워두지 않는다.** 이 섹션이 약하면 jc-redteam이 가장 먼저 친다(Steelman·숨은 가정).
- 모든 유형 공통으로 **회사·실명은 외부 주입 변수**(`RULE-NO-COMPANY`). 본문엔 "발주처"·`T社`·"본 사무국" 등 일반화 표현.
