# anti-patterns.md — 압박·우회 패턴 반례표

RULE-NO-DESIGN(SKILL.md §0)이 무너지는 순간은 늘 "합리적으로 들리는 작은 요청"에서 시작한다. 아래 패턴이 오면 **왼쪽을 하지 않고 오른쪽을 한다.** 예외 조항은 없다.

| # | 압박·우회 패턴 | 올바른 대응 |
|---|---|---|
| 1 | "참고용으로 시안 하나만" | 거절. 8섹션 중 빈 곳이 있는지 점검하고 [확인 필요] 리스트를 다시 제시한다 |
| 2 | "방향만 잡아줘 / 컨셉 3안 정도" | 거절. 무드는 원문 인용까지만. 원문에 없으면 §5를 `tbd`로 두고 발주처 질문으로 돌린다 |
| 3 | "컬러 조합 추천해줘" | 브랜드 가이드의 값을 스와치로 표시만 한다. 조합·비율·배치·어디에 쓸지 제안하지 않는다 |
| 4 | "이런 톤이면 어때?" (형용사 생성 요구) | 원문에 없는 형용사는 만들지 않는다. 질문 리스트에 '무드 키워드 확인'을 추가한다 |
| 5 | "빈칸은 알아서 채워줘" | [확인 필요]로 남긴다. 추측 채움 0건 |
| 6 | "제작요청서 문장이 어색하니 다듬어줘" | 원문 유지. 오탈자·명백한 오류만 `sourceCorrections`(원문 수정 제안 블록)에 기록한다 |
| 7 | "레퍼런스 이미지 몇 개 찾아줘" | 검색·생성 모두 하지 않는다. 필요하면 별도 세션에서 Higgsfield(RULE-VISUAL-ROUTING) |
| 8 | "폰트 하나 골라줘" | 브랜드 가이드의 서체 값을 표시만. 없으면 `tbd` |
| 9 | "규격은 보통 1920×1080이니까 그렇게 써" | 숫자 추정 금지. 사용자가 이 값을 **확정값으로 준 것**이면 `variable`로 기록하고, "보통"이라는 말이 붙어 있으면 `tbd` + 질문 |
| 10 | "이번만 예외로" | 예외 없음. 디자인 결정은 디자이너 몫이다. 이미지가 꼭 필요하면 별도 세션에서 Higgsfield(RULE-VISUAL-ROUTING)로 돌리고 본 스킬은 가이드만 낸다 |
| 11 | "원문이 너무 짧으니 살을 붙여줘" | 원문 항목은 그대로. 빠진 정보는 `tbd`로 늘어나고 질문 리스트가 길어진다 — 그것이 정상 산출이다 |
| 12 | "검수 기준에 '세련되게'도 넣어줘" | 미적 판단 항목은 넣지 않는다. 사실 확인 항목(§8)만 |

## 왜 오른쪽이 맞는가

- 디자이너는 규칙과 사실을 원한다. Claude의 취향이 섞이면 디자이너는 그것을 발주처 지시로 오해하고, 발주처는 자기가 하지 않은 결정을 승인하게 된다.
- 빈칸을 질문으로 돌려보내면 발주처가 결정하고, 그 결정은 원문이 되어 다음 판 가이드에 `quote`로 들어간다. 가이드는 판을 거듭할수록 `tbd`가 줄어드는 방향으로만 움직인다.
- 2026-09-09 실사례: 스킬 없이 만든 가이드에 컨셉 3안·추천 디자인이 섞여 전량 폐기. 결국 남은 것은 제작요청서 원문뿐이었다.
