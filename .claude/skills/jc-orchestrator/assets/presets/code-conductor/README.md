# 프리셋: code-conductor — Code 비용 라우팅 + 강제 게이트

Claude Code 실행 레이어의 **모델 비용 라우팅**(최상위 계열 지휘 / 상위 계열 실행 / 경량 계열 잡무)과 **물리 강제 게이트**(PreToolUse 훅)를 켜고 끄는 스위치형 프리셋. html-pt가 '기능 축' 팀이라면, 본 프리셋은 '모델 티어 축' — 두 축은 직교하며 동시 사용 가능하다.

- **출처**: 외부 가이드 "Fable 5 오케스트레이션"(2026-07-04자) 스펙 흡수. jc 표준(에이전트 템플릿 정규화·RULE 준수·실측 검증 체크) 적용
- **핵심 통찰**: 지침(CLAUDE.md)만으로는 위임이 권고에 그친다 — 지휘자의 직접 코드 수정을 훅으로 물리 차단해야 토큰이 실제로 절약된다. 구독(정액) 환경에서는 절약 대상이 달러가 아니라 **사용량 한도(세션 처리량)와 지휘 컨텍스트 품질**이다

  - ✅ 웹 검증: advisor 툴 실재(2026-04-09 베타 출시) / Claude Code 네이티브 `/advisor` 지원(v2.1.98+, Fable 5 메인은 v2.1.170+)

  - ✅ 게이트 로직 자체는 빌드 시 9개 시나리오 시뮬레이션 통과(차단·재수정 무카운트·서브 통과·비코드 허용·Bash 우회 차단·턴 리셋·off 통과) — 단, 실환경 훅 연동은 별도 실측

## 4계층 구조

| 계층 | 파일 | 역할 |
|------|------|------|
| ① 선언 | `fable.md` | 지휘-위임 지침. CLAUDE.md가 심링크(active.md) 경유로 임포트 |
| ② 역할 배정 | `agents/deep-reasoner.md` · `agents/runner.md` | 심층 추론(상위 계열·effort max) / 잡무(경량 계열·읽기 도구) |
| ③ 리매핑(선택) | `env.sh` | sonnet 지정 서브에이전트를 상위 계열로 승격하는 래퍼 |
| ④ 강제 게이트 | `hooks/orchestration-gate.py` | 메인의 직접 코드 수정을 턴당 2파일로 제한(PreToolUse) |
| 스위치 | `fable-toggle.sh` | `fable on/off/status` — 본체는 한 폴더, 설정 파일엔 로딩 코드만 |

※ 'fable' 명칭은 스위치 식별자일 뿐 특정 모델 세대에 종속되지 않는다 — 세대 교체 시 fable.md의 라우팅 계열과 에이전트 모델 ID만 재검토(경로·명령은 유지 가능). 게이트 상태 폴더 `~/.claude/fable/state/`는 스크립트가 자동 생성한다.

## 설계 원칙 (게이트)

1. **서브에이전트는 차단하지 않는다** — 훅 페이로드의 agent_id/agent_type 존재 여부로 메인과 구분(위임이 실행 경로다)
2. **fail-open** — 게이트 오류 시 차단이 아니라 통과(게이트 버그가 세션을 마비시키지 않게)
3. **코드 파일만 제한** — 문서·설정 직접 수정은 허용(왕복 비용 방지). Bash 우회(sed -i·리다이렉트·tee)는 차단
4. **완벽한 차단막이 아니라 폭주 방지 장치** — 지침(①)과 물리 장치(④)를 겹으로 운용

## advisor 참조 (SDK 구현 불필요)

실행자가 스스로 판단해 상위 모델에 상담하는 역방향 패턴은 Claude Code에 네이티브 내장 — `/advisor` 명령으로 advisor 모델을 선택하면 된다(끄기: `/advisor off`). 본 프리셋(지휘-위임)과 상보 관계: 복잡 멀티스텝을 통째로 맡길 땐 본 프리셋, 싼 모델 주도 + 간헐 상담은 `/advisor`.

## jc-orchestrator와의 관계

- 본 프리셋은 kickoff-code.md의 '위임 모델' 원칙을 실환경 장치로 구현한 것
- html-pt 등 기능 축 팀과 병행 시: 팀 구성은 §2 프로토콜대로, 각 에이전트의 모델 티어는 본 프리셋 원칙대로
