# 킥오프 템플릿 — Chat (순차 역할 스위칭)

## 실행 의미론 (정직 선언)

Chat은 **단일 컨텍스트**다. 에이전트는 격리된 실행 주체가 아니라 **순차로 전환하는 관점 프레임**이다. 이 한계는 약점이 아니라 특성이다 — 격리가 없으므로 핸드오프 손실도 없다. 대신 컨텍스트 누적이 빠르므로 턴 예산 관리가 핵심이다.

## 킥오프 블록 (구성안 승인 직후 1회 제시)

```
── [프로젝트명] Chat 순차 킥오프 ──
에이전트 순서 : <A1 → A2 → (A3∥A4 관점 병기) → A5>
턴 계획      : <턴별 담당 에이전트·산출물 — 턴당 1역할 원칙>
승인 포인트   : <Phase 경계마다 — 승인 없이는 다음 역할 전환 금지>
산출물 보관   : <아티팩트 / 파일 — 턴별 산출 명칭 규칙>
컨텍스트 예산 : <예상 총 턴 수. 초과 조짐 시 새 챗 분리 제안 기준>
──
```

## 운영 규칙

1. **턴당 1역할** — 한 턴에 여러 에이전트 관점을 섞지 않는다. 예외: 독립 관점 2개의 짧은 병기(리서치 요약 + 데이터 요약)는 허용하되 각 관점을 구획으로 분리
2. **역할 전환 승계** — 새 역할 착수 시 직전 역할 산출의 **핵심 3줄 요약**을 서두에 승계 명시(무엇을 받았고 무엇을 낼지)
3. **산출물은 실물로** — 역할 산출은 아티팩트 또는 파일로 남긴다. "대화에 있으니 됐다"는 금지 — 챗에만 있는 산출은 실종된다
4. **승인 포인트 = Phase 경계** — 매 턴 승인은 과잉, Phase 경계 승인은 필수
5. **컨텍스트 초과 대응** — 예산 초과 조짐 시 즉시 보고하고, 완료 Phase 산출물 요약 + 잔여 계획을 담은 **새 챗 이관 블록**을 발행
