# 킥오프 템플릿 — Code (서브에이전트 병렬)

## 실행 의미론 (정직 선언)

Code의 서브에이전트는 **동시 호출이 가능하지만 컨텍스트가 격리**된다. 에이전트 간 실시간 양방향 피드백은 불가능하다 — A가 작업 중에 B의 지적을 받아 고치는 구조가 아니라, A 완료 산출을 B가 파일로 받아 라운드 단위로 반영하는 구조다. **"병렬 팀"이라는 표현은 의존성 없는 노드의 동시 실행에만 쓴다**(2026-05 html-pt 실증: 8에이전트 순차 파이프라인을 병렬 팀으로 표현했다가 정정한 사례 — 재발 금지).

## 킥오프 블록 (세션 첫 메시지에 명문화 — 병렬 세션 정본 규칙)

```
── [프로젝트명] Code 서브에이전트 킥오프 ──
에이전트 배치 : .claude/agents/<slug>.md × N (표준 템플릿 준수)
의존성 그래프 : <순차 체인> / 병렬 노드: <독립 노드만 — 판정 근거 1줄>
쓰기 경계    : <에이전트·세션별 담당 경로 — 겹침 0>
커밋 권한    : <누가 커밋하는가 — 서브에이전트 직접 커밋 금지 여부 명시>
완료 신호    : PROGRESS.md 1줄 로그 + outputs/ 산출 파일
위임 모델    : 복잡 판단=주력 최상위 계열 / 문서·데이터 가공=중간 계열 / 추출·변환=경량 계열
             (구체 버전은 사용자 운영 체계의 권장표 참조 — 하드코딩 금지)
──
```

## Task 호출 표준 지시문 (모든 서브에이전트 호출에 적용)

```
[에이전트: <slug>]
입력: 다음 파일을 반드시 읽고 시작 — <outputs/... 경로 목록>   ← 생략 금지
과업: <출력 계약에 정의된 산출 1개>
출력: <경로/파일명·형식> 에 저장
완료 보고: 산출 경로 + 핵심 결정 3줄 + 미해결 이슈(있으면)
```

- **입력 경로 생략 = 정보 누락 확정.** 서브에이전트는 메인 대화를 보지 못한다. "앞 단계를 참고해" 같은 지시는 금지 표현
- 완료 보고의 '핵심 결정 3줄'은 메인이 다음 호출의 입력 요약으로 재사용한다

## 운영 규칙

1. **병렬은 판정 후에만** — 의존성 그래프에서 독립임을 확인한 노드만 동시 호출. 확신 없으면 순차
2. **메인 검수 의무** — 모든 서브에이전트 산출은 메인 모델이 검수 후 채택. 무검수 체이닝 금지
3. **쓰기 경계·커밋 권한은 킥오프에서만 정의** — 진행 중 변경은 킥오프 블록 공식 개정으로만
4. **라운드 동기화** — 에이전트 간 상호 반영이 필요하면 '라운드'(전원 산출 → 메인 취합 → 수정 지시 일괄 배포)로 설계한다. 실시간 협의처럼 묘사하지 않는다
5. **완료 신호** — PROGRESS.md 로그 없는 작업은 크로스디바이스에서 실종된 것으로 간주

## 비용 라우팅·강제 게이트 (code-conductor 프리셋)

위임 모델 원칙을 실환경 장치로 굳히려면 [`../assets/presets/code-conductor/`](../assets/presets/code-conductor/README.md)를 설치한다(설치·실측 검증: 동 폴더 INSTALL.md — Code 세션 소관).

- **지휘-위임 구도**: 지휘자는 계획·분배·검수·판단만. 직접 처리는 1~2개 파일의 사소한 수정·문서/설정 변경·단순 조회까지만 허용(전부 위임하면 왕복 비용이 역전)
- **게이트 차단 시 대응**: 재시도 금지 — 차단 메시지의 라우팅 안내대로 즉시 서브에이전트에 위임한다
- **지침과 장치의 겹 운용**: CLAUDE.md 지침은 권고일 뿐 — 물리 차단(PreToolUse 훅)과 함께 써야 위임이 강제된다
- **역방향 패턴**: 싼 모델이 주도하고 어려운 지점만 상위 모델에 상담하는 구조는 Claude Code 네이티브 `/advisor`로 해결(프리셋 README 참조)
