# 킥오프 템플릿 — Cowork (파일 경계 병렬)

## 실행 의미론 (정직 선언)

Cowork는 메인 세션이 **다수 작업 스레드를 파일 경계로 병렬 관리**하는 구조다. 진짜 동시 실행 주체가 여럿인 것이 아니라, 긴 세션 안에서 독립 작업 트랙들이 파일 단위로 병행된다. 따라서 충돌 방지의 단위는 프로세스가 아니라 **파일·경로**다.

## 킥오프 블록

```
── [프로젝트명] Cowork 병렬 킥오프 ──
작업 폴더    : <연결된 작업 폴더 경로 — 산출물은 이 폴더에 직접 저장(별도 outputs 하위폴더 금지)>
쓰기 경계    : <에이전트별 담당 경로/파일 — 겹침 0 확인>
  · A1(<아키타입>) → <경로/파일 패턴>
  · A2(<아키타입>) → <경로/파일 패턴>
병렬 구간    : <의존성 없는 트랙 목록> / 순차 구간: <선행→후행>
완료 신호    : PROGRESS.md 1줄 로그 (형식: 날짜 | 에이전트 | 산출 파일 | 상태)
메인 검수    : <각 트랙 완료 시 메인이 검수 후 다음 구간 개방>
──
```

## 운영 규칙

1. **쓰기 경계 겹침 0** — 두 트랙이 같은 파일을 편집하는 계획은 킥오프에서 반려. 공통 파일(인덱스류)은 메인 세션만 쓴다
2. **경계 변경은 공식 개정으로만** — 진행 중 "이 파일도 건드릴게" 류 암묵 확장 금지. 킥오프 블록을 개정 재제시 후 진행
3. **완료 신호 의무** — 트랙 완료마다 PROGRESS.md에 1줄. 신호 없는 트랙은 미완료로 간주
4. **저장 규칙** — 산출물은 연결된 작업 폴더에 직접 저장. 임의 하위폴더 신설 금지(폴더 표준 구조 준수)
5. **메인 검수 게이트** — 병렬 트랙 산출은 메인 검수 통과 후에만 하류 입력으로 사용
