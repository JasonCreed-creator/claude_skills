## §1. 아키텍처 — 불변과 가변

| 계층 | 성격 | 내용 |
|---|---|---|
| 문법 (불변, 스킬 내재) | 본 문서 + slide-types + deck_kit | 7원칙 · 그리드 · 타입 16종 · 카피 규칙 · 안티패턴 |
| 변수 (가변, 매 건 주입) | 브리프로 수집 | 콘텐츠 · 스토리라인 · 밀도 모드 · 테마 · 에셋 |

## §2. 7원칙 (모드·테마 무관)

1. **주장형 헤드라인** — 본문 슬라이드 제목은 주장을 싣는다. 어투는 용도로 분기한다.
   - **제안서(발주처 제출용 — RFP·비딩·위탁 대응)**: `proposal-voice.md` §3의 한국어 제안서 어투가 정본이며 본 절과 충돌하면 그쪽이 우선한다. 명사형 종결 주장 카피('~제공'·'~구축'·'~설계'·'~확보'·'~보장')가 기본, 문장형('~합니다')은 콘셉트·클로징·강조 지점에만. 주어 생략·번역투 금칙 8·25자 내외 한 주장.
   - **그 외 덱(소개서·발표덱·결과보고·스폰서 덱)**: 완결된 주장 문장. 명사구 금지. SIMPLE은 마침표 종결 원칙, CUSTOM은 생략형 감성 카피 허용.
   - 공통: 주장 없는 명사구('운영 계획'·목차 문구 전재)는 어느 쪽이든 금지. 강조 키워드만 accent + '따옴표'.
2. **한 슬라이드 = 한 메시지** — 핵심 하나. 텍스트는 키워드 중심, 문장은 짧게.
3. **네비게이션 일관성** — 아이브로우/브레드크럼 + 푸터 전 슬라이드 반복. 현재 위치가 항상 보인다.
4. **숫자는 크게, 근거와 함께** — 주장마다 근거. 핵심 수치는 KPI 카드로. 깨알 표는 그래프 1 + 핵심 수치 1로 재구성.
5. **구조 도해 우선** — 텍스트 나열 대신 비교 프레임·스텝·넘버링 카드·진행 pill.
6. **섹션 디바이더 리듬** — 고스트 넘버 + 섹션명으로 챕터 전환을 크게 끊는다.
7. **바텀 테이크어웨이·CTA 클로징** — 밀도 슬라이드는 하단 한 줄 결론. 마지막 장은 반드시 행동 요청.

## §3. 구성 엔진 파이프라인

1. **메시지 추출**: 콘텐츠 소스에서 [주장 | 근거 숫자 | 구조(단계·비교·목록) | 증빙(실적·인용)] 분류 태깅
2. **스토리라인 조립**:
   - 설득형(세일즈·스폰서·투자): 문제/타깃 정의 → 자격 증명 → 제안 구조 → 가치 환산 → 논리 보강 → 희소성 클로징
   - 대응형(비딩·RFP·위탁): 제안 개요 → 제안사 현황 → 제안 내용 → 수행 방안 → 관리 계획 (발주처 지정 목차 최우선)
   - 보고형: 결론 선행 → 성과 데이터 → 분석 → 향후 계획
   - 자유형: 사용자 목차 그대로
3. **타입 매핑**: 콘텐츠 신호 → T01~T16 (`slide-types.md` 선택 가이드). 넘치면 분할, 부족하면 병합
4. **카피 변환** (§6) → 5. **테마 적용** (`themes.md`) → 6. **빌드** → 7. **검수** (§7)

## §4. 밀도 모드

| | SIMPLE | CUSTOM |
|---|---|---|
| 용도 | 핵심 요약·설득 (짧은 미팅·경영진·스폰서) | 고밀도 상세 (비딩 제안서·운영계획) |
| 분량 | 15~35장 | 50~80장 |
| 밀도 | 도형 ~16/장, ~300자 | 도형 30~45/장, 450~650자, 이미지 3~4+ |
| 자동 판정 신호 | 세일즈·스폰서·경영진·요약 | RFP·위탁·국가계약·운영계획 |

## §6. 카피 문법

**변환 규칙**: 받은 명사구 소제목 → 주장 문장으로 재작성(제안서는 명사형 종결 주장 카피로 — `proposal-voice.md` §3-1). 근거 숫자가 있으면 문장 안으로. 강조 키워드만 accent + '따옴표'.

**제안서 우선권**: 발주처 제안서의 카피·문체·표기·금칙은 본 절보다 `proposal-voice.md`(§3 어투·번역투 금칙 8 · §4 표기 · §6 금칙 수식어)가 우선한다. 아래 패턴 5종 중 제안서에는 voice §3과 겹치는 1(대조 병치 §1-9)·2(숫자 선행)·3(쉼표 호흡 대구)만 쓰고, 4(세일즈 긴장 클로징 — 제안서 클로징은 사업 고유 메시지, 게이트 9)·5(3연 동사 — 쉼표 2개, 한 주장 위반)는 쓰지 않는다.

**패턴 5종** (콘텐츠 무관 적용)
1. 부정→긍정 반전: "~하지 않습니다. ~합니다."
2. 숫자 선행 주장: "OO은 평균 N명이 결정합니다."
3. 전환 선언(쉼표 호흡): "A를, B로."
4. 긴장 클로징: "이 자리는 채워집니다. 당신이 아니면, 경쟁사가." (클로징 한정)
5. 3연 동사 리듬: "잇고, 넘고, 채웁니다" (비전·콘셉트 한정)

**금칙**: 노골적 세일즈 어투 / 공포 마케팅 / 스펙 나열 / 근거 없는 단언("업계 1위"·"혁신적")

## §7. 안티패턴 8종 ('기계 생성 티' — check_deck.py 기계 검수)

1. 흰 박스+회색 테두리 나열만으로 채운 슬라이드 (리스트의 박스화)
2. 테마 토큰 외 색 (Tailwind slate 잔재 등)
3. 이미지·텍스처 0장 데크
4. 명사구 제목 잔존 — 제안서는 '주장 없는' 명사구만 해당(명사형 종결 주장 카피는 정상). check_deck `--voice proposal`은 A4를 끄고 어투 V1~V7을 검사
5. 모든 요소 동일 크기·동일 위계 (핵심 1개는 커야 한다)
6. 24pt 미만 깨알 표 방치
7. 네비게이션 누락 슬라이드
8. CTA 없는 클로징 ("감사합니다" 단독)
