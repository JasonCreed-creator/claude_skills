# Model Guide — 권장 모델 병기 기준

브리프 말미의 "권장 모델" 병기 기준. **RULE-VERSION-FACTS** 적용 문서 — 시점 종속 팩트는 계열명 우선 + 검증일 병기, 기억에 의한 기록 금지. 정본: `jc-design-system/references/shared-rules.md#RULE-VERSION-FACTS`.

## 1. 원칙

- **계열명 우선**: 브리프에는 스냅숏 ID("claude-xxx-YYYYMMDD")가 아니라 **계열명**("Opus 계열", "Sonnet 계열")으로 쓴다. 브리프는 사람이 읽는 카드이고, 계열명은 세대가 바뀌어도 부패하지 않는다.
- **권유만, 변경은 사용자**: 모델·작업량은 UI 토글로 사용자가 정한다. Claude는 자동 변경할 수 없으므로 브리프의 권장 모델은 **권유**다 — 현재 설정과 다르면 "전환 권장"으로 표기하고 이유 1구를 붙인다.
- **작업량(effort)도 함께**: 권장 모델 뒤에 작업량 등급을 괄호로 병기할 수 있다 — 예: "Sonnet 계열 (High)". 등급 표기는 Max/High/Medium/Low로 통일한다(운영 규칙 정본의 한국어 표기 '최대'는 Max에 대응).

## 2. 작업 유형 → 권장 계열 매핑

| 작업 유형 | 권장 계열 / 작업량 | 근거 |
|----------|------------------|------|
| 복잡 전략 · GO/NO-GO 판단 · 납품 직전 최종 마무리 | 최상위 추론 계열 / Max | 뒤집기 비용이 가장 큰 결정 |
| 표준 제안서 · 분석 · 코딩 · 대시보드 빌드 | Sonnet 계열 / High | 품질·속도 균형 |
| 메일 · 회의록 정리 · 문서 다듬기 | Sonnet 계열 / Medium | 정형 작업 |
| 단순 확인 · 대량 변환 · 반복 처리 | Haiku 계열 / Low | 속도·비용 우선 |

- "최상위 추론 계열"은 시점에 따라 다르다 — §3의 현행 스냅숏을 참조해 카드에는 당시의 계열명을 쓴다.
- 기본값이 이미 최상위 + 최대인 환경이면 하향 권유는 대량·반복 작업일 때만 한다.

## 4. 카드 표기 예

```
권장 모델: Sonnet 계열 (High) — 표준 빌드 작업
권장 모델: Mythos-class 최신 (Max) — GO/NO-GO 판단, 전환 권장
권장 모델: Haiku 계열 (Low) — 대량 변환, 하향 권유
```
