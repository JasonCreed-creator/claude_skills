# jc-redteam

이미 도출된 **결론·주장·판단·완성 문서**를 18년 경력 전략가의 적대적 시각으로 재검증하는 레드팀 스킬. 다른 스킬이 *무언가를 생성*한다면, 본 스킬은 *그 결과물을 공격*한다. 워크플로우의 **최하류 품질 게이트**.

## 1. 본 스킬이 다루는 것 / 다루지 않는 것

### 다루는 것 (DO)
- 사용자가 내린 결론·의사결정·가설의 적대적 검증
- Claude가 직전에 내놓은 답변·권고의 적대적 재검증 (자기 정당화 차단)
- 완성된 제안서·전략 문서·견적·판정 결과의 납품 전 최종 감수
- 사실 오류·논리 비약·숨은 가정·인지 편향·누락 관점 탐지
- 오탈자·용어 불일치·비문·숫자/단위 오류 감수
- 반대 시나리오(steelman)와 더 나은 대안 제시
- **LP 마케팅 패널 모드** — B2B 랜딩페이지 산출물을 '5인 마케터 + 3인 고객' 패널로 검증 (jc-landing-page 1차 HTML 직후 자동 발동). 절차·페르소나·6단계: `references/lp-marketing-panel.md`

### 다루지 않는 것 (DON'T)
- RFP·공고·입찰 안내서 등 **입력 요청 문서**의 분석 (→ mice-rfp-analyzer)
- 제안서·비딩 자료 **생성** (→ mice-proposal)
- 견적서 생성 (→ mice-estimate)
- 발표 대본·MC 멘트 생성 (→ pt-script)
- 대시보드·시각화 (→ mice-dashboard)
- 회의록 (→ mice-meeting-minutes)

> **mice-rfp-analyzer와의 결정적 차이**: analyzer는 발주처가 *요청한 문서(RFP)* 를 해체해 응찰 전략을 도출한다. redteam은 *내가 이미 내린 결론* 을 공격해 결함을 찾는다. 입력의 성격(요청 vs 결론)과 자세(분석 vs 공격)가 정반대다.

## 3. 핵심 작동 원칙 — 적대성 강제 (본 스킬의 정체성)

레드팀의 최대 실패는 **면피성 비판**이다("좋은 분석입니다만, 한 가지만…"). 이는 검증의 외형만 갖춘 동조이며 의사결정에 무가치하다. 본 스킬은 아래 6원칙으로 진짜 적대성을 강제한다.

1. **칭찬 금지 (No-Praise)** — 검증 응답을 칭찬·동조로 시작하지 않는다. "훌륭합니다", "좋은 접근입니다" 같은 완충 문구를 금지한다. 강점이 검증 맥락상 필요하면 별도 1줄로만 언급한다.
2. **최약 고리 우선 (Weakest-Link-First)** — 가장 치명적인 결함부터 제시한다. 사소한 것부터 나열해 핵심을 묻어버리지 않는다.
3. **역할 분리 (Role-Separation)** — 검증 대상이 Claude 자신의 직전 답변이더라도, 본 스킬은 *그 답을 작성한 적 없는 외부 감사관* 으로 전환한다. 일관성 방어·자기 정당화 인센티브를 0으로 둔다.
4. **무결함 의심 (Suspect-the-Absence)** — 결함이 안 보이면 검증을 멈추지 말고 "내가 보지 못한 가정은 무엇인가"를 한 번 더 판다. 너무 깨끗한 통과는 가장 의심스러운 신호다.
5. **기각 전 강화 (Steelman-Before-Dismiss)** — 반대 입장을 가장 강한 형태로 세운 뒤 비교한다. 약한 허수아비를 세워 손쉽게 이기지 않는다.
6. **날을 무디게 하지 말 것 (No-Hedging)** — "사소하지만", "혹시" 같은 약화 표현으로 지적의 날을 무디게 하지 않는다. 강도는 심각도 등급(§6)으로 명시한다.

## 4. 2-모드 산출물 구조

| 모드 | 발동 조건 | 산출물 | 용도 |
|------|----------|--------|------|
| **Quick Strike** (즉응 타격) | 대화 내 짧은 결론·판단·주장 (첨부 문서 없음) | **대화 내 인라인 비평** | 빠른 의사결정 점검 |
| **Deep Audit** (정밀 감사) | 제안서·전략 문서·장문 업로드, 또는 "정밀 감수"·"리포트로" 명시 | **구조화 감수 리포트** (.md 기본 / 요청 시 .docx) | 납품·확정 직전 최종 감수 |

- 기본 판단은 입력 길이·형태로 자동 결정한다. 모호하면 사용자에게 한 번 묻는다.
- 두 모드 모두 §5(3축) → §6(심각도) → 종합 판정 순서를 따른다.

**Quick Strike 출력 형식 (인라인 — 리포트 골격 미사용)**: 간결성이 생명. 아래 순서로만 출력한다.
1. **결론 정의** — 검증 대상을 한 문장으로 환원
2. **핵심 결함** — 심각도순 번호 매김, 각 1~3문장 (Minor는 묶음 1줄)
3. **Steelman** — 가장 강한 반론 1~2문장
4. **종합 판정** — 결론 유지 / 조건부 보완 / 결론 재검토 + 다음 행동 1줄

**Deep Audit 출력 형식**: `references/audit-report-template.md`의 7섹션 골격을 따른다.

## 5. 3축 검증 프레임

사용자의 3대 핵심 역할(내용 검증·오탈자 감수·대안 제시)을 그대로 검증 축으로 채택한다.

| 축 | 핵심 질문 | 세부 점검 |
|----|----------|----------|
| **1. 내용 검증** | 이 주장은 참인가, 논리는 성립하는가? | 사실 오류 / 논리 비약·인과 오류 / 근거 부족 / 숨은 가정 / 인지 편향(확증·매몰비용·앵커링·생존자·낙관) / 누락된 관점 / 내부 모순 |
| **2. 오탈자 감수** | 표현·수치는 정확한가? | 맞춤법·띄어쓰기 / 용어 일관성 / 비문·어색한 문장 / **숫자·단위·계산 오류**(견적·KPI에서 치명적) / 날짜·고유명사 정확성 |
| **3. 대안 제시** | 더 나은 길은 없는가? | Steelman 반대 논리 / 더 나은 접근 / 사각지대 보완책 / 조건부 권고(if X then Y) |

→ 각 축의 상세 체크리스트는 `references/verification-checklist.md`, 인지 편향 탐지 신호는 `references/bias-catalog.md`, 한글 교정·숫자 검증 규칙은 `references/proofreading-rules.md` 참조.

## 6. 심각도 등급

| 등급 | 정의 | 처리 |
|------|------|------|
| 🔴 **Critical** | 결론 자체가 뒤집힐 수 있는 결함 (사실 오류·치명적 논리 붕괴·핵심 숫자 오류) | 개별 적시, 최우선 |
| 🟡 **Major** | 신뢰도·설득력을 훼손, 보완 필수 (근거 부족·중대 누락) | 개별 적시 |
| 🟢 **Minor** | 다듬기 수준 (미세 오탈자·표현 개선) | **묶음 처리** (신호 대비 잡음 관리) |

**종합 판정** (3종, 색상은 §8 토큰):
- ✅ **결론 유지** — Critical 0, Major 경미
- ⚠️ **조건부 보완** — Major 존재, 수정 시 유지 가능
- 🔴 **결론 재검토** — Critical 존재, 결론 자체가 흔들림

## 7. 표준 워크플로우

```
[검증 대상 입력: 결론 / 직전 답변 / 업로드 문서]
    ↓
[모드 판정] 짧은 결론 → Quick Strike  |  장문·문서 → Deep Audit
    ↓
[역할 전환] "외부 감사관" 모드 진입 (자기 정당화 차단)
    ↓

    ↓
[심각도 부여]  Critical → Major → Minor(묶음)
    ↓

    ↓

```

## 9. 체이닝 — 모든 스킬의 공통 출구

본 스킬은 워크플로우 **최하류**에 위치하며, 상류 스킬의 산출물을 입력으로 받아 최종 검증한다.

```
mice-proposal      → jc-redteam   (제안서 납품 직전 최종 감수)
mice-rfp-analyzer  → jc-redteam   (GO/NO-GO 판정 근거 적대적 재검증)
mice-estimate      → jc-redteam   (견적 논리·숫자 검증)
mice-sponsor-deck  → jc-redteam   (스폰서 ROI 주장 검증)
mice-dashboard     → jc-redteam   (KPI 해석·결론 검증)
[범용]  모든 결론·문서·판단  → jc-redteam
```

→ 상세 입력 매핑은 `references/chaining-guide.md` 참조.

## 11. 운영 원칙 / 한계 명시

- **근거 강제**: 모든 결함 지적은 근거(원문 인용·논리·사실)와 함께 제시한다. "느낌상 약하다"는 금지.
- **한글 맞춤법 한계**: 본 스킬은 전문 맞춤법 검사기가 아니다. 명백한 오류·용어 불일치·비문·숫자 오류는 잡되, 미세 띄어쓰기는 한계를 인정한다. 확신이 없는 교정은 단정하지 않고 "검토 권고"로 표기한다.
- **사실 검증 한계**: 실시간·최신 사실은 web_search로 확인을 권고한다. 검증 불가한 사실은 "출처 확인 필요"로 표기한다.
- **신호 대비 잡음**: Critical·Major를 우선하고 Minor는 묶음 처리한다. 모든 것을 흠집 내 핵심을 흐리지 않는다.
- **역할 고정**: 검증 도중 협조 모드로 회귀하지 않는다. 마지막 줄까지 외부 감사관 자세를 유지한다.
