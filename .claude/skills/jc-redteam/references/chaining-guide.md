# 체이닝 가이드 (타 스킬 → jc-redteam)

> jc-redteam은 워크플로우 **최하류 품질 게이트**다. 상류 스킬의 산출물을 입력으로 받아 최종 검증한다. 입력은 **명시적 JSON이든 단순 파일/텍스트든 모두 수용**한다(엄격한 스키마 강제 없음). 단, 산출물 유형마다 **집중 공격 포인트**가 다르므로 아래 매핑을 따른다.

> **봉투 정본**: 공통 `ChainPayload/v1` 봉투 구조·전체 워크플로우(본 스킬의 최하류 게이트 위치 포함)·표준 규약은 [jc-design-system/references/chaining-protocol.md](../../jc-design-system/references/chaining-protocol.md) §5 참조. 단, **본 스킬은 봉투 유무와 무관하게 모든 산출물·텍스트를 수용**하므로 봉투 스키마를 강제하지 않는다. 본 문서는 jc-redteam **고유의 산출물 유형별 집중 검증 포인트**만 정의한다.

## 입력 수용 원칙

1. 상류 스킬이 산출한 **최종 결과물**(PPTX/XLSX/DOCX/HTML/JSON 또는 결론 텍스트)을 그대로 받는다.
2. 검증 대상의 **핵심 주장(결론)** 을 먼저 한 문장으로 정의한 뒤 검증을 시작한다.
3. 산출물 유형 → 권장 모드(Quick/Deep)는 아래 기준. 모호하면 묻지 않고 Deep Audit로 진행하며 고른 모드를 한 줄로 밝힌다.
4. 검증은 산출물을 **재생성하지 않는다.** 결함을 찾아 지적·교정·대안 제시까지만 한다(생성은 원 스킬의 몫).

## 스킬별 집중 검증 포인트

### jc-pptx (제안서·소개서·스폰서 덱 PPTX)
- **권장 모드**: Deep Audit
- **집중 공격 포인트**:
  - 기획 논리의 비약 — "콘셉트 → 효과" 사이 인과가 성립하는가
  - 평가 기준 대응 충실도 — RFP 평가 항목별로 빠짐없이 답했는가 (`coverage_map` 대조, 누락 관점)
  - 운영 리스크·예비비·계약 대응 누락 (화려한 기획 뒤의 빈 곳)
  - 숫자 일관성 — 본문 인원/일정/예산이 견적·일정표와 충돌하지 않는가
  - 과장 표현 — 근거 없는 "최고/유일/보장" 류
  - (스폰서 덱) ROI 주장의 근거 — 노출·리드·전환 수치가 추정인가 보장인가, Tier 혜택 매트릭스의 가격-혜택 역전
  - 명의·식별정보 — 발행 명의 리멤버 MICE비즈팀, 구 소속사 상호·고객사 실명(동의 미확인) 0건 (`RULE-NO-COMPANY`)

### mice-rfp-analyzer (GO/NO-GO 판정)
- **권장 모드**: Deep 또는 Quick (판정 분량에 따라)
- **집중 공격 포인트**:
  - GO 판정의 **숨은 가정** — 승률 추정의 근거는? 낙관편향은?
  - 독소 조항 평가절하 — 리스크를 과소평가하지 않았는가
  - 경쟁사·승률 추정의 근거 — 추정을 사실처럼 쓰지 않았는가 (기저율 무시)
  - NO-GO 판정이라면 — 매몰비용·현상유지 편향으로 기회를 버리는 것은 아닌가

### mice-estimate (견적 XLSX)
- **권장 모드**: Deep Audit
- **집중 공격 포인트** (숫자 검증 최우선):
  - 자릿수·단위·합계 검산 (`proofreading-rules.md` §5 전면 적용)
  - 기획료율·VAT·할인·절사 규칙이 실제 숫자에 일관 적용됐는가
  - 항목 누락 — 필수 비용 항목이 빠지지 않았는가
  - 단가 적정성 — 시장가 대비 과소/과대 (확인 불가 시 "검토 권고")
  - 게런티/인원 기준이 제안서·RFP와 일치하는가 (내부 모순)

### mice-ops-docs · mice-run-of-show (운영계획서·KPI 대시보드·큐시트)
- **권장 모드**: Deep Audit
- **집중 공격 포인트**:
  - 책임자·기한 누락, 임계 경로의 단일 실패점, 비상 대응의 실행 가능성
  - 큐 타이밍 합계·전환 시간이 프로그램 총 시간과 맞는가
  - KPI 해석의 인과 착각·사후확신 편향, 불리한 지표 누락(확증편향)

### mice-aftermath (결과보고)
- **권장 모드**: Deep Audit
- **집중 공격 포인트**:
  - 성과가 목표 대비로 제시됐는가(목표 없는 실적 나열)
  - 케이스 재사용(R1~R3) 시 익명화·동의 플래그 준수
  - 교훈·차기 권고가 데이터에서 실제로 도출됐는가

### jc-strategy-canvas · mice-market-intel (전략 캔버스·시장 리서치)
- **권장 모드**: Deep Audit
- **집중 공격 포인트**:
  - `[가설]/[추정]` 비중이 높은 권고를 단정하지 않았는가 (`evidence_flags`)
  - 시장 규모·점유 수치의 출처 티어·단일 출처 여부 (`gaps`)
  - 경쟁 대안·NO-GO 시나리오를 steelman 했는가

### mice-meeting-minutes (회의록)
- **권장 모드**: Quick Strike
- **집중 공격 포인트**:
  - Action Item의 책임자·기한 누락
  - 결정사항이 실제 발언·합의와 일치하는가
  - 미결 사항이 결정된 것처럼 기록되지 않았는가

### jc-doc-coauthor (산문 문서 — 행사 기획서·운영계획서·전략 메모·의사결정 문서·RFC·메시지 기획 문서)
- **권장 모드**: Deep Audit (전략 메모·메시지 기획 문서는 분량이 짧아 Quick Strike)
- **공통 공격 포인트**:
  - 실행 안전성 — 문서대로 실행하면 어디서 깨지는가(책임자·기한·의존성 공백, 선언만 있고 실행 수단이 없는 대응)
  - 숨은 가정 — 틀리면 결론·권고가 무너지는 미검증 전제
  - 내부 모순 — 섹션 간 주장·일정·인력 배치가 서로 충돌하지 않는가
  - 섹션 간 수치 정합 — 인원·일정·예산·KPI 숫자가 섹션마다 같은가(`proofreading-rules.md` §5)
- **문서 유형별 추가 포인트** — jc-doc-coauthor는 Stage 3에서 문서 유형을 함께 넘긴다. 이 표가 정본이다(구 `mice-doc-types.md` 차용 표를 2026-10-09 이관).

| 유형 | 추가 공격 포인트 |
|------|------------------|
| 행사 기획서 | "콘셉트 → 기대효과" 인과 비약 · 모객 가정의 낙관편향(기대 인원 근거가 사실인가 희망인가) · 운영 리스크·예비비 누락 · 과장 표현("최고/유일/최대") |
| 운영계획서 | 아래 §mice-ops-docs 포인트 + 협력사 의존 항목의 계약·백업 공백 · 타임라인과 인력 배치 충돌 · 임계 경로의 단일 실패점 |
| 전략 메모 | 논거의 사실/추정 구분 · 확증편향(유리한 근거만 모았는가) · 버린 대안을 허수아비로 세웠는가 |
| 의사결정 문서 | §mice-rfp-analyzer의 숨은 가정·낙관편향 · 매몰비용·현상유지 편향 · 옵션 트레이드오프의 불리한 면 은폐 · 되돌릴 수 없는 결정을 되돌릴 수 있다고 오판 |
| RFC | 문제 → 해법 인과 비약 · 대안 기각 사유의 정당성 · 영향·의존성 과소평가 · Open Questions가 실은 결론을 흔드는 미결인지 · Steelman 후 더 나은 접근 |
| 메시지 기획 문서 | ★추천안 근거가 포지셔닝 한 문장과 실제로 이어지는가 · 버린 안을 허수아비로 세웠는가 · 상표·도메인·기존 행사명 충돌을 [확인 필요]로 남겼는가 · 국문·영문·약칭 표기 일관 |

결과보고 산문은 jc-doc-coauthor가 아니라 mice-aftermath 산출로 받는다(§mice-aftermath).

### jc-kv-guide (KV 제작 가이드 HTML·MD)
- **권장 모드**: Quick Strike
- **집중 공격 포인트**:
  - 추측 채움 — 원문에 없는 항목을 [확인 필요] 없이 단정하지 않았는가(모든 항목에 출처 태그)
  - 디자인 제안 혼입 0건 — 컨셉 안·추천 디자인·시안·레이아웃·컬러 조합 제안·무드보드·레퍼런스 이미지가 섞이지 않았는가(RULE-NO-DESIGN)
  - 규격·검수 기준 누락 — 매체별 사이즈·해상도·파일 형식·필수 요소·검수 체크 기준이 빠지지 않았는가
  - 발주처 확인 질문 리스트가 [확인 필요] 항목과 1:1로 대응하는가

### mice-slack-ops (공지·발주처 메일·캔버스·브리프 초안)
- **권장 모드**: Quick Strike (발송·게시 전)
- **집중 공격 포인트**:
  - 사실 — 날짜·기한·금액·담당·행사 ID가 원 스레드·봉투와 일치하는가
  - 수신자 — 대외(발주처) 글에 금액·마진·내부 일정·내부 채널 정보가 새지 않는가, 멘션·대상이 맞는가
  - 톤 — 내부 해요체 / 대외 합니다체 분기, 첫 줄 결론
  - 발송 불가역 — 한 번 나가면 회수할 수 없다는 전제로 오해 소지·단정 표현을 최종 점검(발송은 사용자 승인 후)

### jc-skill-forge (스킬 인테이크 감수 — 신규·개정 스킬)
- **권장 모드**: Deep Audit ('스킬 인테이크 감수')
- **집중 공격 포인트**:
  - 트리거 정확도 — description 키워드가 실제 발화에 걸리는가, 형제 스킬 트리거와 부딪히는 near-miss는 없는가
  - 형제 중복 — 다른 라이브 스킬 역량을 반복하지 않는가(MERGE 검토), 경계 선언이 양방향으로 대칭인가
  - 금지 문구 — 폐지 게이트·폐합 스킬명·구 모델 ID·금지 호칭·구 시그니처 값(`jc-skill-forge/references/house-conventions.md`)
  - 외부 스크립트 보안 — 흡수한 외부 코드의 네트워크·파일 쓰기·셸 실행, 검토 전 실행·포함 여부
  - lint 대조 — `lint_skills.py` ERROR 0 주장이 실제 재실행 출력과 일치하는가(증거 병기)

## 범용 입력 (스킬 외 결론·문서)

상류 스킬을 거치지 않은 일반 결론·판단·문서도 동일하게 받는다.
- 짧은 결론·판단 텍스트 → **Quick Strike**
- 업로드된 장문 문서·전략 자료 → **Deep Audit**
- "방금 네 답변 검증해봐" → **Quick Strike** + 역할 분리(외부 감사관) 엄격 적용

→ 모드 판정 후 `verification-checklist.md`의 3축 순서로 검증을 실행한다.
