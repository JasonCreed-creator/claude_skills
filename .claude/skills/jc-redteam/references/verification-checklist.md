## 사용법

- 탐지 질문에 "예/모르겠다"가 나오면 그 지점이 결함 후보다.
- 결함 후보는 반드시 **근거(원문 인용·논리·사실)** 와 함께 적시한다. "느낌상 약하다"는 금지.
- 인지 편향 상세는 `bias-catalog.md`, 한글·숫자 검증 상세는 `proofreading-rules.md` 참조.

## 축 1 · 내용 검증

이 주장은 참인가, 논리는 성립하는가.

### 1-1. 사실 오류
- **정의**: 검증 가능한 수치·날짜·고유명사·인용이 틀렸거나 출처 불명.
- **탐지 질문**: 이 수치/날짜/이름은 어디서 왔는가? 출처가 있는가? 최신인가? 내가 확인할 수 있는가?
- **예시**: "작년 동종 행사 참가자 3만 명" → 출처는? 추정인가 확인인가? / "경쟁 PCO 5개사" → 근거 있는 집계인가 인상인가?
- **심각도**: 결론을 떠받치는 핵심 사실이면 🔴 Critical, 부차적이면 🟡 Major.
- **처리**: 검증 불가 시 web_search 권고 또는 "출처 확인 필요" 표기. 단정하지 않는다.

### 1-2. 논리 비약 · 인과 오류
- **정의**: 전제에서 결론으로 가는 단계가 생략되거나, 상관을 인과로 착각.
- **탐지 질문**: A에서 B로 가는 중간 단계가 빠졌는가? 상관관계를 인과로 단정했는가? "A 아니면 B"라는 거짓 양자택일인가?
- **주요 유형**: 선후관계=인과 착각(post hoc) / 성급한 일반화 / 거짓 딜레마 / 미끄러운 비탈 / 순환 논증.
- **예시**: "보유 DB가 크다 → 따라서 모객이 보장된다" (DB 규모 ≠ 전환율) / "작년 행사가 성공했다 → 올해도 성공한다" (조건 변화 무시).
- **심각도**: 결론의 주 논증 사슬에 걸리면 🔴 Critical.

### 1-3. 근거 부족
- **정의**: 주장의 강도에 비해 근거가 빈약하거나, 일화를 데이터로 사용.
- **탐지 질문**: 이 주장의 근거는 무엇인가? 근거가 주장만큼 강한가? 표본이 충분한가? 한두 사례를 일반 법칙으로 쓰고 있는가?
- **예시**: "이 포맷이 시장 트렌드다" (근거 1건?) / "고객이 원한다" (몇 명에게, 어떻게 확인했나?).
- **심각도**: 보통 🟡 Major. 근거 없이 대규모 투자·수주를 정당화하면 🔴 Critical.

### 1-4. 숨은 가정
- **정의**: 결론이 성립하려면 참이어야 하지만 명시되지 않은 전제.
- **탐지 질문**: 이 결론이 성립하려면 무엇이 참이어야 하는가? 그 전제는 명시됐는가, 암묵적인가? 전제가 깨지면 결론은 어떻게 되는가?
- **추출법**: 결론을 부정해보고 "그래도 이게 참이려면?"을 역산한다.
- **예시**: "연 매출 5억 목표" → 숨은 가정: 연 20건 × 평균 단가 + 수주율 100% + 노쇼 0 + 단가 미하락. 각 가정의 현실성은?
- **심각도**: 깨지기 쉬운 핵심 가정이면 🔴 Critical.

### 1-5. 인지 편향
- **정의**: 판단을 왜곡하는 체계적 사고 오류. → 상세 탐지 신호는 `bias-catalog.md`.
- **빠른 점검**: 확증편향(유리한 근거만 모았나?) / 매몰비용(이미 투자해서 계속하나?) / 앵커링(첫 숫자에 고정됐나?) / 낙관편향(베스트 케이스만 봤나?) / 생존자편향(성공 사례만 봤나?).
- **심각도**: 결론의 방향을 틀어버리는 편향이면 🔴 Critical~🟡 Major.

### 1-6. 누락된 관점 (사각지대)
- **정의**: 결론이 특정 이해관계자·시나리오를 고려하지 않음.
- **탐지 질문**: 누가 이 결론에 반대할까? 그들은 뭐라고 할까? 어떤 이해관계자가 빠졌나? 어떤 시나리오(최악/규제/경쟁 반응)가 누락됐나?
- **관점 체크리스트**: 발주처 / 경쟁사 / 협력사 / 내부 운영팀 / 재무 / 법무·계약 / 최종 고객(참가자).
- **예시**: 제안서가 화려한 기획만 있고 운영 리스크·예비비·계약 독소조항 대응이 비어 있다.
- **심각도**: 의사결정을 좌우하는 관점 누락이면 🔴 Critical~🟡 Major.

### 1-7. 내부 모순
- **정의**: 문서 앞뒤가 충돌하거나, 숫자·일정·용어가 서로 어긋남.
- **탐지 질문**: 앞과 뒤가 충돌하는가? 숫자 합이 맞는가? 일정이 동시에 가능한가? 같은 용어를 다르게 쓰는가?
- **예시**: 3쪽 "참가 200명" vs 7쪽 "150명 기준 견적" / 일정표상 준비 2주인데 본문 "6주 소요".
- **심각도**: 핵심 숫자·일정 모순이면 🔴 Critical.

## 축 2 · 오탈자 감수

표현·수치는 정확한가. → 상세 규칙은 `proofreading-rules.md`. 여기서는 점검 영역만.

| 점검 영역 | 핵심 질문 | 비고 |
|----------|----------|------|
| 맞춤법·띄어쓰기 | 명백한 오류·자주 틀리는 패턴이 있는가? | 미세 띄어쓰기는 한계 인정, "검토 권고"로 |
| 용어 일관성 | 같은 개념을 다른 표기로 섞어 쓰는가? | 예: "참가자/참석자/게스트" 혼용 |
| 비문·어색한 문장 | 주어-서술어가 호응하는가? 번역투·중복은? | |
| **숫자·단위·계산** | **자릿수·단위·합계·비율이 맞는가?** | **MICE 최우선 — 견적 한 자리 = 10배** |
| 날짜·고유명사 | 요일과 날짜가 일치하는가? 회사명·인명 표기가 정확한가? | |

> **숫자 오류는 오탈자가 아니라 사실 오류급으로 취급한다.** 견적·KPI에서 한 자리 차이는 결론을 통째로 뒤집는다 → 🔴 Critical.

## 축 3 · 대안 제시

더 나은 길은 없는가. 비판으로 끝내지 않고 **건설적 출구**를 제시한다.

### 3-1. Steelman 반대 논리
- **방법**: 결론에 반대하는 가장 똑똑한 사람을 상정하고, 그가 펼칠 **최강 논리**를 구성한다. 그다음 원 결론과 정면 비교한다.
- **금지**: 약한 허수아비를 세워 손쉽게 이기지 않는다(§3 원칙 5).
- **출력 형식**: "이 결론에 대한 가장 강한 반론은 X다. 원 결론의 방어 논리는 이를 막아내는가, 아닌가?"

### 3-2. 더 나은 접근
- **탐지 질문**: 같은 목표를 더 적은 리스크/비용/시간으로 달성하는 길은 없는가? 결론이 국소 최적(local optimum)에 갇혔는가?
- **예시**: "전면 신규 개발" 결론 → "기존 검증 자산 재활용 + 부분 신규"가 리스크·비용 모두 낮지 않은가?

### 3-3. 사각지대 보완책
- 축 1-6에서 발견된 누락 관점에 대한 **구체적 보완 제안**을 단다.
- 예시: 운영 리스크 누락 발견 시 → "예비비 N% + 핵심 협력사 이중화 + 우천 시 대안 동선" 제안.

### 3-4. 조건부 권고
- **형식**: "결론은 조건 C 하에서만 유효하다. C가 충족되지 않으면 대안 D로 전환하라."
- 결론을 통째로 부정하기보다 **조건화**하여 실행 가능한 형태로 만든다.

## 검증 실행 순서

```
1. 검증 대상 1회 통독 — 핵심 주장(결론)이 무엇인지 한 문장으로 정의
2. "외부 감사관" 모드 진입 — 이 결론을 옹호할 이유 0
3. 축 1 내용 검증 — 1-1 ~ 1-7 탐지 질문 순회, 결함 후보 수집
4. 축 2 오탈자 감수 — 특히 숫자·단위·계산 검산
5. 축 3 대안 제시 — Steelman → 더 나은 접근 → 보완책 → 조건부 권고
6. 심각도 부여 — Critical → Major → Minor(묶음)
7. 무결함 의심 — 결함이 거의 없으면 "내가 못 본 핵심 가정은?"을 1회 더 점검
8. 종합 판정 — 결론 유지 / 조건부 보완 / 결론 재검토
```
