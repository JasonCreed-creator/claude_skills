# 체크인 · 체크아웃 — 2파일 규칙 정본

---

## 1. CLAUDE.md (불변 컨텍스트)

- 개정 주체는 사용자뿐. 에이전트는 수정하지 않는다(사용자가 "CLAUDE.md에 반영해"라고 지시한 결정만 예외).
- 필수 절: 세션 리추얼 · 프로젝트 정의(한 줄 경계 포함) · 확정 결정 표(D1~Dn, 일자) · 작업 규칙 · 폴더 구조 · 권장 모델·사고 수준 · 쓰기 경계·금지 · 완료 기준(DoD).
- 결정은 번호를 매기고 변경 시 SPEC 개정을 동반한다. "다시 묻지 않는다"로 종결된 결정은 그렇게 표기한다(예: 저장소 공개 유지).
- 정본 우선순위를 적는다: 사용자 현재 지시 > SPEC > 브리프 > 원본 자료. 충돌 시 상위를 따르고 PROGRESS 결정 로그에 남긴다.

## 2. PROGRESS.md (가변 상태)

7항목을 항상 유지한다.

| 항목 | 내용 |
|------|------|
| 상태 요약 | 단계(체크리스트) · 최신 산출 · 한 줄 상태 |
| 완료 | 체크박스 목록(게이트 수치 포함) |
| 미결·열린 질문 | 사용자 결정 필요 항목, 번호 붙여 |
| 다음 스텝 | 누가(사용자/에이전트) 무엇을 |
| 결정 로그 | `날짜 · 결정 — 주체` |
| 세션 로그 | `날짜 · 서피스·모델 · 한 일` |
| 세션 잠금 | 현재 작업 중인 머신/세션 또는 "(없음)" |

추가 절: 환경 메모(이 PC 제약, 도구 경로) · 체크아웃 절(날짜별 누적) · 다음 세션 시작 순서.

## 3. 체크인

```
1. CLAUDE.md 전체 + PROGRESS.md의 "현재 상태"와 마지막 "체크아웃 — 날짜" 절을 읽는다.
2. 3줄 복명:
   현재 상태: …
   이번 세션 목표: …
   열린 질문: … (없으면 "없음")
3. 복명 후 바로 개시한다(승인 대기 없음). 잠금이 다른 머신으로 기록돼 있거나 고밀도 산출물의 기획안 확인이 필요할 때만 멈추고 묻는다.
4. 환경 확인: 로컬 PC인지 클라우드 세션인지 (windows-env.md) — 게이트 실행 가능 여부가 갈린다.
```

사용자 지시가 "체크아웃 절부터 읽고 '새 세션 첫 작업 순서' 1~6번 진행"처럼 구체적이면 복명을 짧게 하고 바로 실행한다.

## 4. 체크아웃

트리거: 세션 종료, 컨텍스트 한도 임박("컨텍스트 꽉 차서 새 세션으로"), 사용자 퇴근("나 집에 가도 돼?"), 요청 1건 완료.

```
1. PROGRESS.md 7항목 갱신 + "## 체크아웃 — YYYY-MM-DD (서피스 · 모델 · 요지)" 절 추가
   - 산출 파일(경로·줄 수), 게이트 결과 수치, SPEC 이탈, 미결·질문, 남은 것(사용자 몫), 주의
2. "다음 세션 시작 순서" 1~N번 (읽을 절 · 먼저 할 일 · 확인할 것)
3. git 저장소면: git fetch → 원격 확인 → 커밋(메시지 `<작업/스킬>: <요약>`). push는 사용자 또는 settings 허용 시.
4. 채팅에 체크아웃 보고 블록 출력 (아래 형식). 서피스를 바꿔 검수할 때는 사용자가 이 블록을 붙여 넘긴다.
```

### 체크아웃 보고 블록

```
[<프로젝트> · <작업명> 체크아웃 보고]
- 산출 파일: (경로별 1줄, 줄 수 또는 바이트)
- 빌드/테스트: (명령 · 통과/전체)
- 실렌더·화면 검증: (방식 · 스크린샷 경로 · 콘솔 에러 수)
- SPEC 이탈: (항목·사유) 없으면 "없음"
- 미결·질문: (사용자 결정 필요 항목)
- 다음 액션: (검수 요청 / 배포 / 사용자 할 일)
```

## 5. 세션 인계 (컨텍스트 한도)

- 새 세션 첫 메시지 권장형: `<폴더>에서 이어서. PROGRESS.md의 "체크아웃 — <날짜>" 절과 "다음 세션 시작 순서"를 읽고 시작. (결정 답: …)`
- 백그라운드 서브에이전트가 살아 있으면 체크아웃에 task-id와 산출 경로를 적는다. 다음 세션은 그 산출을 파일로 확인하고 필요하면 파일 단위로 새 에이전트를 띄운다(재개 메시지는 안 통하는 경우가 많다).
- 확인 필요 항목은 번호를 유지한다(예: "확인 9건 중 2번 해소, 3~9 대기") — 세션이 바뀌어도 같은 번호로 부른다.

## 6. 잠금 · 동시성

- 한 폴더 = 동시 1세션. 두 머신(집·회사 노트북)에서 같은 폴더를 동시에 열지 않는다. Drive 동기화 폴더면 시작·종료 시 동기화 완료를 확인.
- 클라우드 세션(GitHub)과 로컬 세션이 같은 저장소를 쓰면 로컬은 커밋 전 `git fetch`로 원격 병합 여부를 먼저 본다(2026-09-16 리베이스 사례).

## 7. 호칭 · 언어

- 사용자는 "기획자님". 산출물·UI·주석·보고는 한국어. 영어는 코드 문법·변수명·고유명사만. 업계 약어(PCO·A/V·sqm)는 팀원 누구나 읽히게 풀어 쓴다.
- 브라우저 대화상자(alert·confirm) 금지, 민감 정보(단가·급여·개인 연락처)는 어느 산출물에도 두지 않는다 — 프로젝트별 금지 목록은 CLAUDE.md가 정본.
