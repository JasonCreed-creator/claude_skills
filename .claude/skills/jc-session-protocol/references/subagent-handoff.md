# 서브에이전트 · 병렬 · 핸드오프 정본

에이전트 사이를 흐르는 것은 대화가 아니라 **파일**이다. (2026-09-21 구 jc-orchestrator의 handoff-protocol · kickoff-code · kickoff-cowork · agent-catalog 흡수)

---

## 1. 실행 의미론 (정직 선언)

| 서피스 | 의미론 |
|--------|--------|
| **Code** | 서브에이전트는 동시 호출 가능하나 **컨텍스트 격리**. 실시간 양방향 피드백 불가 — A 완료 산출을 B가 파일로 받아 라운드 단위로 반영. "병렬 팀"은 의존성 없는 노드의 동시 실행에만 쓰는 말 |
| **Cowork** | 메인 세션이 다수 작업 트랙을 **파일 경계로 병행 관리**. 충돌 방지 단위는 프로세스가 아니라 파일·경로 |
| **Chat** | 단일 컨텍스트에서 역할을 순차 전환. 에이전트 = 관점 프레임. 턴당 1역할 |

## 2. 핸드오프 7칙

1. **입력 명시 의무** — 호출 시 읽을 파일 경로를 열거. 금지 표현: "앞 단계를 참고해", "위에서 한 대로", "맥락 알지?"
2. **출력 계약** — 산출 경로·파일명·형식을 호출 전에 계약. 파일명 `<NN>-<slug>-<요지>.<ext>`로 순번이 의존성을 가시화
3. **의존성 판정** — 선행 산출이 입력이면 순차, 독립이면 병렬, 상호 반영이면 라운드(전원 산출 → 메인 취합 → 수정 지시 일괄). 확신 없으면 순차
4. **완료 신호** — `날짜 | 에이전트 | 산출 파일 | 상태(완료/부분/차단)` 1줄을 PROGRESS.md에. 신호 없는 작업은 미완료
5. **쓰기 경계** — 킥오프에서 에이전트별 경로를 겹침 0으로 선언. 공통 파일은 메인 전담. 변경은 킥오프 개정으로만
6. **실패 핸드오프** — 계약 산출을 낼 수 없으면 중단 보고(사유 + 시도 + 대안 1개). 조용한 스펙 축소·임의 대체 금지. 메인이 조건부 진행/재호출/개정 중 판정
7. **메인 검수 의무** — 모든 서브에이전트 산출은 메인이 검수 후 채택. 무검수 체이닝 금지

## 3. 병렬 스텝 탐지

두 스텝이 ⓐ 같은 파일을 쓰지 않고 ⓑ 서로의 출력을 입력으로 삼지 않으면 병렬 후보. 공통 기반(데이터 계약·스키마·토큰) 스텝을 먼저 완료한 뒤 그 위에 얹히는 독립 구현을 병렬 디스패치한다. 실증 분할: ① 서버 `Code.gs` ② 화면 `src/app.js`·`styles.css` ③ 문서·테스트 → 메인이 계약 기준으로 병합.

안티패턴: 과분할(핸드오프 비용 > 이득) · 순차화된 병렬(독립인데 직렬) · 모호한 핸드오프(입력 경로 없음).

```
의존성 그래프 : <순차 체인> / 병렬 노드: <독립 노드 — 판정 근거 1줄>
쓰기 경계    : <에이전트별 담당 경로 — 겹침 0>
커밋 권한    : 메인만 (서브에이전트 직접 커밋 금지) · 저장소 전체 git 명령(stash·reset·checkout) 병렬 중 금지

```

## 6. 운영 제약 (실증)

- 백그라운드 에이전트는 PC 절전·앱 종료·600초 무진행이면 스톨로 죽고, 이전 세션 에이전트는 재개 메시지가 닿지 않는다 → 산출 파일을 확인하고 파일 단위로 새 에이전트를 띄운다.
- 사용자가 "지금 멈춘 거 아니지?", "내가 뭘 기다려야 해?"라고 물으면 진행 중인 에이전트·예상 완료·사용자가 할 일 없음을 한 줄로 답한다.
- 사용자에게 필요한 조작(회사 계정 배포, 삭제, OAuth 승인)은 처음부터 사용자 몫으로 분리해 체크아웃 "남은 것"에 적는다.
