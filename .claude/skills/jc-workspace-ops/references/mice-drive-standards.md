# MICE Drive 운영 표준 — 정본

`jc-workspace-ops`가 Google Drive MCP 도구를 조합할 때 따르는 **폴더 위계·배치·권한·트래커 표준**의 권위 정의다. SKILL.md는 요지만 담고, 세부 트리·매트릭스·점검표는 본 문서를 정본으로 참조한다.

> **RULE-NO-COMPANY**: 아래 모든 폴더명·파일명·컬럼 예시에서 회사명·개인 실명·부서명은 하드코딩하지 않는다. `행사약칭`·`발주처`·`담당` 등은 일반화 슬롯이며, 실제 값은 외부 주입 변수(`{{client_company}}`·`{{author_name}}` 등)로 매 산출 시 주입한다. 정본: `jc-design-system/references/shared-rules.md#RULE-NO-COMPANY`.

---

## 1. 행사별 표준 폴더 위계

**원칙**: 행사 하나 = 최상위 폴더 하나. 그 아래 번호 접두 표준 트리를 둔다(번호 접두로 정렬 안정성 확보).

```
[행사약칭]_[연도]/
├── CLAUDE.md           # 세션 연속성 2파일 — 템플릿 전개, 불변(목표·규칙·세션 리추얼)
├── PROGRESS.md         # 세션 연속성 2파일 — 템플릿 전개, 가변(매 세션 갱신). 세션 진입점이므로 루트 노출
├── 00_행정/            # 계약·발주 문서, 사업자·인허가, 보험, 대외 공문
├── 01_기획/            # 기획서·운영계획서·큐시트·컨셉·전략 메모
├── 02_견적·정산/       # 견적서, 발주·지출 내역, 정산서, 단가표 (내부 전용)
├── 03_회의록/          # 킥오프·정기·발주처 협의·사전답사·협력사 회의록
├── 04_운영/            # 진행 트래커, 체크리스트, 연락처, 일정표, 리스크 로그
├── 05_산출물/          # 최종 납품물(디자인·인쇄·영상·데이터), 발주처 미공유 원본
├── 06_발주처공유/      # 발주처와 공유하는 폴더 — 송부 확정본만 (권한 위생 대상)
└── 99_archive/         # 구버전·폐기 후보·종료 자료
```

**시리즈(정기·회차) 행사**: 상위에 시리즈 폴더를 두고, 회차마다 위 표준 트리를 반복한다. 세션 2파일은 시리즈 상위·`_공통/`에는 두지 않고 회차 폴더 루트에만 전개한다(세션 단위 = 회차 폴더).

```
[시리즈약칭]/
├── _공통/                     # 회차 불변 자산(브랜드·템플릿·누적 트래커)
├── [연도][회차]_[행사약칭]/   # 표준 트리 반복
└── ...
```

**세팅 절차**: 신규 착수 시 `create_file`(mimeType `application/vnd.google-apps.folder`)로 최상위 → 하위 폴더 8종을 순서대로 생성(`parentId` 체이닝). 이어서 `claude workspace/00_CONTEXT/templates/`의 `_TEMPLATE-CLAUDE.md`·`_TEMPLATE-PROGRESS.md`를 `copy_file`로 행사 폴더 루트에 각각 `CLAUDE.md`·`PROGRESS.md`로 전개하고, 전개 직후 플레이스홀더(`{{…}}`)에 프로젝트 값(프로젝트명·목표·산출물 스펙·행사약칭·개정일 등)을 주입한다. 이때 템플릿에도 전개본에도 회사명·개인 실명을 하드코딩하지 않는다(**RULE-NO-COMPANY** — 템플릿은 플레이스홀더만 담고, 실제 값은 주입 변수로 채운다). 기존 폴더는 트리와 대조해 누락 폴더만 보강하고, 오배치 문서는 §3 배치 규칙으로 재배치 권고(이동은 사용자 수행).

## 2. 문서 세트 배치 매트릭스

| 문서 종류 | 지정 폴더 | 생성 스킬(경계) | 발주처 공유 |
|---|---|---|---|
| 계약·발주·공문 | `00_행정` | (외부/수기) | 원본 미공유, 필요 시 06에 사본 |
| 기획서·운영계획서 | `01_기획` | mice-proposal / jc-doc-coauthor | 확정본만 06 |

| 발주처 송부 확정본 | `06_발주처공유` | — (배치만) | **공유 대상** |
| 세션 2파일(CLAUDE.md·PROGRESS.md) | 행사 폴더 루트 | 본 스킬(템플릿 전개) | **미공유(내부 전용)** |

**철칙**: `06_발주처공유`에는 **송부가 확정된 산출물만** 둔다. 내부 초안·정산 원본·단가표·미확정 기획안은 절대 06에 두지 않는다 — 폴더 공유 권한이 하위 전체에 상속되므로, 06에 놓인 순간 내부 문서가 발주처에 노출된다(§4 권한 위생과 직결).

**파일명 규약**: `YYMMDD_행사약칭_문서종류_vN` (예: `260712_[행사약칭]_기획서_v3`). 버전은 `vN`으로만 증가시키고, 구버전은 삭제하지 말고 `99_archive`로 권고 이동. 날짜는 문서 확정일 기준. 단, 세션 2파일(`CLAUDE.md`·`PROGRESS.md`)은 고정 파일명이며 본 규약·중복 판정·아카이브 권고 대상에서 제외한다(세션 진입점).

## 3. 배치·정합 절차

1. `search_files`로 대상 행사 폴더와 산재 문서를 수집(`title contains`·`fullText contains`·`parentId =`).
2. `get_file_metadata`로 종류·수정시각 확인, §2 매트릭스로 올바른 폴더 판정.
3. 오배치·미배치 문서를 **배치 권고 목록**으로 산출(어느 파일 → 어느 폴더, 이유).
4. 신규 생성물은 `create_file`(지정 `parentId`)로 바로 표준 위치에. 기존 파일 이동은 MCP에 이동 도구가 없으므로 사용자가 Drive UI에서 수행하도록 안내(대안: `copy_file`로 정위치 사본 생성 후 원본 아카이브 권고).

## 4. 발주처 공유 권한 위생 점검표 (점검·안내 전용)

`get_file_permissions`(읽기 전용)로 대상을 읽고, 아래 항목을 진단한다. **스킬은 위험을 표면화·안내만 하고, 권한 변경은 전적으로 사용자가 Drive UI에서 수행한다**(MCP에 권한 변경 도구 없음 — 구조적 강제).

| # | 점검 항목 | 위험 신호 | 권장 조치(사용자 수행) |
|---|---|---|---|
| P1 | 링크 공개 범위 | `type: anyone`(링크 있는 모두) | 특정 사용자·도메인으로 제한 |
| P2 | 외부 도메인 권한 | 발주처 외 도메인에 `writer`/`owner` | reader로 강등 또는 제거 |
| P3 | 내부 문서 노출 | 정산·단가·초안이 `06_발주처공유` 하위 | 02/05로 이동, 06에서 제거 |
| P4 | 과다 편집 권한 | 열람이면 되는데 `writer` 다수 | 필요 최소 권한 원칙으로 축소 |
| P5 | 잔존 공유 | 종료 행사에 활성 외부 공유 | 종료 시 공유 해제 |
| P6 | 상속 오인 | 폴더 공유가 하위 전체 상속됨을 미인지 | 폴더 단위 공유 전 하위 구성 재확인 |

**점검 흐름**: (1) 대상 폴더/파일 id 확보(`search_files`) → (2) `get_file_permissions`로 각 permission의 `type`·`role`·`emailAddress`/`domain` 읽기 → (3) 위 표로 위험 분류 → (4) `위험 항목 + 권장 조치 + Drive UI 단계`를 출력. 사용자 승인·수행 전에는 아무 것도 바뀌지 않는다.

## 5. 시트 기반 체크리스트·트래커 스키마

운영 상태의 정본은 `04_운영`의 Google Sheets 트래커다. `create_file`(mimeType `application/vnd.google-apps.spreadsheet`)로 신규 생성, 기존은 `read_file_content`로 읽어 정리.

**표준 진행 트래커 컬럼**

| 컬럼 | 내용 | 값 규약 |
|---|---|---|
| 항목 | 업무·태스크명 | 자유 |
| 영역 | 기획/운영/디자인/정산/대외 등 | 고정 카테고리 |
| 담당 | 담당자 슬롯 | 실명 금지 — 역할/이니셜 또는 주입 변수 |
| 상태 | 진행 상태 | `대기`·`진행`·`보류`·`완료` (mice-meeting-minutes 칸반 TODO·DOING·BLOCKED·DONE과 대응) |
| 기한 | 마감일 | `YYYY-MM-DD` |
| 우선순위 | 중요도 | `높음`·`보통`·`낮음` |
| 비고 | 링크·메모 | 관련 파일 링크 |

**체크리스트(단계 게이트)**: 착수·리허설·본행사·철수·정산 등 국면별 체크 항목을 별도 탭으로. 컬럼은 `항목 / 완료(Y·N) / 확인자 / 일자 / 근거링크`.

**상호 참조**: 회의록(mice-meeting-minutes)의 Action Item과 트래커 항목은 상태 값을 맞춘다. 단 회의록 생성은 그 스킬 몫이고, 본 스킬은 트래커의 *컬럼·상태 규약·정본 위치*만 소유한다.

## 6. 정기 정리(청소) 루틴

1. `search_files`로 유사 제목·`Copy of`·버전 중복 후보 수집 — 단, 행사마다 루트에 존재하는 동명 세션 2파일(`CLAUDE.md`·`PROGRESS.md`)은 설계상 중복이므로 후보에서 제외한다.
2. `get_file_metadata`로 `modifiedTime`·`owner` 비교 → 정본(최신·소유자 일치) vs stale 판정.
3. 산출: **정본 지정 + stale 목록 + 조치 권고**(`99_archive` 이동 / 병합 / 개명). 이동·삭제 실행은 사용자 확인 후 사용자가 수행하며, **삭제는 스킬이 절대 수행하지 않는다**(영구 삭제 금지 — 아카이브 이동으로 대체 권고).
4. 청소 주기: 행사 국면 전환 시(착수·본행사 후·정산 완료 후) + 시리즈 회차 종료 시.
