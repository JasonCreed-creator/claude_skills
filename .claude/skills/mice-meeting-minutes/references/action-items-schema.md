# Action Items Schema — 5열 표준 + 우선순위 자동 추정

본 스킬의 Action Items는 5열 표준으로 정규화한다.

---

## 1. 5열 표준 정의

| 열 | 영문 | 데이터 형식 | 필수/선택 | 기본값 |
|----|------|------------|----------|--------|
| Owner | 책임자 | TEXT | 필수 | (호스트) |
| Due | 기한 | DATE (YYYY-MM-DD) | 필수 | (미팅일+7일) |
| Priority | 우선순위 | ENUM (P0/P1/P2/P3) | 필수 | P2 |
| Status | 상태 | ENUM (TODO/DOING/BLOCKED/DONE) | 필수 | TODO |
| Linked | 연결 | TEXT | 선택 | (없음) |

추가 부가 열:
| ID | 자동 생성 식별자 | TEXT | 필수 | (자동) |
| Action | 액션 내용 | TEXT | 필수 | (transcript에서 추출) |
| Source | 발화 시점 | TEXT (HH:MM) | 선택 | (transcript에서 추출) |
| Note | 추가 메모 | TEXT | 선택 | (없음) |

---

## 2. ID 자동 생성 룰

```
[프로젝트 코드]-[회의 코드]-[순번]
```

예시:
- `CA-DISC-001` (고객사A 디스커버리 1차 미팅 1번 액션)
- `CA-DISC-002`
- `RMB-26-001` (RMB REBUILD26 1번 액션)
- `CB-SEM-001` (고객사B 세미나 1번 액션)
- `CFX-BID-001` (ConfEx Bidding 1번 액션)

프로젝트 코드는 `--series` ID 또는 사용자 지정 우선. 미지정 시 프로젝트명에서 자동 약어화.

---

## 3. Owner 추정 룰

### 명시적 발화 우선
```
"제가 ~하겠습니다"      → 발화자
"[이름] 실장님이 ~"     → [이름]
"우리 팀이 ~"           → 호스트 측 팀
"고객사A가 ~"           → 고객사A 측 (구체 인물 미정)
```

### 추정 우선순위
1. 발화 내 명시 인명 매칭
2. "제가/내가" 1인칭 → 발화자
3. "팀/회사" 단위 명시 → 해당 조직 (인물 미정 플래그)
4. 매칭 실패 → 미팅 호스트 기본값 + 재확인 플래그

### Owner 미정 처리
- 미정 비율 30% 초과 시 사용자에게 경고
- 회의록에 "(Owner 재확인 필요)" 표시

---

## 4. Due 추정 룰

### 명시적 발화 우선
```
"내일까지"              → 미팅일+1일
"다음 주까지"            → 미팅일+7일
"이번 달 안에"           → 미팅일이 속한 달 마지막 날
"다음 미팅 전까지"        → 다음 미팅 일정-1일
"5월 15일까지"          → 2026-05-15
"금주 내"               → 미팅일이 속한 주 금요일
```

### 한국어 시간 표현 매핑

| 표현 | 매핑 |
|------|------|
| 즉시 / 오늘 / 바로 | 미팅일 |
| 내일 | 미팅일+1 |
| 모레 | 미팅일+2 |
| 이번 주 / 금주 | 미팅일 속한 주 금요일 |
| 다음 주 | 미팅일+7 |
| 이번 달 / 월말 | 해당 월 마지막 날 |
| 다음 달 초 | 다음 월 5일 |
| 분기 말 | 해당 분기 마지막 날 |

### Due 미정 처리
- 명시 안 된 경우 미팅일+7일 + "(Due 재확인 필요)" 플래그
- 미정 비율 30% 초과 시 사용자에게 경고

---

## 5. Priority 자동 추정 룰

| Priority | 정의 | 매칭 키워드 |
|----------|------|-------------|
| **P0** | 즉시·블로커 | "긴급", "즉시", "오늘 안에", "ASAP", "당장", "지금", "막혔어요", "블로커" |
| **P1** | 금주 처리 | "금주", "이번 주", "빨리", "우선", "다음 미팅 전" |
| **P2** | 통상 (기본값) | (특별 시그널 없는 경우 모두) |
| **P3** | 참고·검토 | "참고", "검토만", "나중에", "여유 있을 때", "시간 되면" |

### 추가 추정 규칙
- 결정사항 직접 후속 Action → P1 이상
- 미결 사항 보류 후 재논의 Action → P2 이하
- 외부 의존(상대방 결재 등) Action → P1 + Status BLOCKED

### Priority 분포 검증
- P0 비율 50% 초과 시 "과도한 P0 분배 — 우선순위 재검토 권장" 경고
- P3 비율 50% 초과 시 "Action이 추적할 가치가 있는지 재검토 권장" 경고

---

## 6. Status 초기값 및 갱신

### 신규 생성 시 기본값
- 일반 Action: `TODO`
- 외부 의존(승인 대기, 결재 대기): `BLOCKED`

### 시리즈 모드(`--series`) carry-over 시 갱신
- 이전 회차 `TODO` → 본 회차에 자동 carry-over (Status 그대로)
- 이전 회차 `DOING` → 진척 발화 매칭하여 `DOING` 유지 또는 `DONE` 갱신
- 이전 회차 `BLOCKED` → 해소 발화 있으면 `TODO/DOING`로 갱신, 없으면 그대로
- 이전 회차 `DONE` → carry-over 제외, 시리즈 누적 시트에만 기록

### Status 갱신 시그널
```
"~ 끝났어요" / "완료했습니다" / "보냈습니다"      → DONE
"~ 진행 중이에요" / "하고 있습니다"              → DOING
"~ 막혔어요" / "기다리는 중" / "결재 대기"        → BLOCKED
"~ 아직 못 했어요" / "내일부터 시작"             → TODO
```

## 7. Linked 필드 활용

### 권장 연결 대상

| 연결 유형 | 표기 예시 |
|-----------|----------|
| 다른 Action | `CA-DISC-001` |
| 결정사항 번호 | `Decision-3` |
| 미결 사항 번호 | `Pending-1` |
| 외부 문서 | `RFP-{{client_company}}-V2.docx` |
| 이슈 트래커 ID | `JIRA-CA-101` |
| 슬랙 메시지 링크 | `slack:T123/C456/p789` |
| 이메일 제목 | `Email: [고객사A] 동시통역 결재` |

### 자동 매핑 시도
- 본 회의록 내 결정사항·미결 사항 번호와 Action 본문 매칭하여 자동 연결
- 명시적 문서·이슈 ID 언급 시 그대로 추출

## 8. Action Items 추출 발화 패턴

### 약속형 (명시 Action)
```
"~할게요" / "~하겠습니다" / "~해드릴게요"
"~까지 보내드립니다" / "~까지 제출하겠습니다"
"~ 확인해보겠습니다" / "~ 알아보겠습니다"
```

### 명령·요청형 (지시 Action)
```
"~해주세요" / "~ 부탁드립니다"
"~ 확인 가능할까요?" / "~ 가능한지 봐주실래요?"
"~ 준비해주시면 좋겠어요"
```

### 합의형 (결정 후속 Action)
```
"그럼 ~로 합시다" / "그렇게 진행할게요"
"~로 가시죠" → 누가 무엇을 어떻게의 후속 Action 자동 도출
```

### 추출 안 함 (혼동 회피)
```
"~할 수도 있어요" — 가정형, Action 아님
"~하면 좋을 것 같아요" — 의견, Action 아님
"~ 검토 중이에요" — 진행 중, Action이 아닌 정보
```

→ 단, 가정형·의견이라도 발화자가 후속 발화에서 약속형으로 전환하면 Action으로 인정.

## 9. Action Items 검증 체크리스트

생성 후 자동 검증:

| 체크 | 기준 | 미달 시 |
|------|------|--------|
| 총 Action 수 | 1개 이상 | "Action 미식별 — 회의록 내용 재확인 필요" |
| Owner 명시 비율 | 70% 이상 | "Owner 다수 미정 — 재확인 권장" |
| Due 명시 비율 | 70% 이상 | "Due 다수 미정 — 재확인 권장" |
| P0 비율 | 50% 이하 | "P0 과다 — 우선순위 재검토" |
| P3 비율 | 50% 이하 | "P3 과다 — 추적 가치 재검토" |
| BLOCKED 비율 | 30% 이하 | "BLOCKED 과다 — 의존성 정리 필요" |

## 10. 시리즈 모드 누적 매트릭스 (`--series`)

`series-tracking.md` 상세 정의 참조. 본 파일은 Action Items 관점만 기록:

### 시리즈 누적 시트 컬럼

| 회차 | 일자 | 신규 Action | 완료 (DONE) | 진행 중 (DOING) | 차단 (BLOCKED) | 미시작 (TODO) | 완료율 |
|------|------|-------------|-------------|-----------------|----------------|---------------|--------|
| 1 | 2026-04-15 | 8 | 6 | 0 | 1 | 1 | 75% |
| 2 | 2026-05-09 | 12 (신규 7 + carry 5) | 9 | 1 | 1 | 1 | 75% |

### Carry-over 표시 규칙
- 본 회차 시트에 carry-over Action 별도 표시 (행 색상 약간 다르게)
- 회차 횟수 누적이 3회 이상이면 "장기 미해결 Action 경고" 출력
