# Analysis Framework — 8축 분석 프레임

본 스킬은 미팅 transcript를 8개 축으로 추출하여 회의록을 구조화한다.

---

## 8축 개요

| 축 | 영문 | 핵심 질문 | 산출 데이터 |
|----|------|----------|-------------|
| 1. 안건 | Agenda | 무엇을 논의했는가? | 번호 매김 목록 |
| 2. 발언 요지 | Discussion | 누가 어떤 입장을 냈는가? | 발화자별 요약 |
| 3. 결정사항 | Decisions | 무엇이 합의되었는가? | 합의 시점·내용·근거 |
| 4. Action Items | Actions | 누가 무엇을 언제까지? | 5열 표준 (별도 파일) |
| 5. 리스크·이슈 | Risks | 어떤 위험이 식별되었나? | Issue·영향도·대응안 |
| 6. 미결 사항 | Pending | 무엇이 미결로 남았나? | 보류 사유·재논의 시점 |
| 7. 후속 일정 | Next Steps | 다음에 무엇이 일어나나? | 일자·참석자·아젠다 |
| 8. 전략 메모 | Strategy Notes | 이 미팅의 전략적 함의는? | 18년 경력 해석 (Internal 모드만) |

---

## 1. 안건 (Agenda)

### 추출 룰
- 미팅 시작 5분 이내 발화에서 "오늘 다룰 내용", "아젠다", "안건은" 키워드 매칭
- 클로바노트 등 transcript에 명시적 안건 표기가 있으면 그대로 활용
- 표기 없으면 발화 흐름의 토픽 전환점을 식별하여 역추정

### 출력 형식
```
1. 행사 컨셉 검토
2. 예산 협의
3. 일정 확정
4. 후속 미팅 일정 조율
```

### 누락 처리
- 안건이 명확히 추출되지 않으면 "안건이 명확히 식별되지 않음. 발화 흐름 기준 토픽 추정" 표기
- 토픽 추정 시 "추정 안건" 라벨 부착

---

## 2. 발언 요지 (Discussion)

### 추출 룰
- 안건별로 발화자 발언을 1~3줄로 압축
- 동일 발화자가 같은 안건에서 여러 번 발언하면 입장 통합
- 핵심 입장이 같은 발화는 중복 표기 금지

### 출력 형식 (Internal 모드)
```
[안건 1: 행사 컨셉 검토]
- 호스트(PCO): 보안 테마 중심 1일 컨퍼런스 + 데모 부스 결합 제안
- 고객사A 김부장: 데모 부스보다 1:1 미팅룸 비중 강조
- 주대웅 실장 (리멤버): 명함 데이터 기반 타겟 참가자 250명 모집 가능
```

### 출력 형식 (External 모드 — 익명화 옵션)
```
[안건 1: 행사 컨셉 검토]
- 호스트(PCO): 보안 테마 중심 1일 컨퍼런스 + 데모 부스 결합 제안
- 클라이언트 측: 데모 부스보다 1:1 미팅룸 비중 강조
- 모집 파트너: 명함 데이터 기반 타겟 참가자 250명 모집 가능
```

### 발화 길이 임계값
- 안건당 발언 요지 총 5줄 초과 시 "(상세 발언은 transcript 참조)" 표기
- 각 발화 압축 최대 3줄

---

## 3. 결정사항 (Decisions)

### 추출 룰
- "결정", "확정", "합의", "OK", "그렇게 합시다", "그걸로 가시죠" 등 합의 시그널 발화 매칭
- 양측 동의 표명이 있는 항목만 결정으로 인정 (한쪽 제안만 있으면 미결로 분류)
- 결정 시점·내용·근거를 함께 기록

### 출력 형식
```
[결정 1] 행사 형식: 1일 컨퍼런스 + 1:1 미팅룸 50%·데모 부스 50% 비중
  - 합의 시점: 미팅 시작 23분
  - 합의 근거: 고객사A 김부장 요구 + 호스트 동의

[결정 2] 행사 일자: 2026년 6월 18일(목)
  - 합의 시점: 미팅 시작 41분
  - 합의 근거: 고객사A 분기 마감 직후 + 베뉴 가용일
```

### 강조 표시
- jc-design-system `color.accent` 박스로 강조
- 결정사항 5건 초과 시 우선순위 정렬 (계약·예산·일정 관련 우선)

---

## 4. Action Items (Actions)

별도 파일 `action-items-schema.md` 정의. 5열 표준(Owner / Due / Priority / Status / Linked).

추출 핵심 룰만 본 파일에 기록:
- 명령형·약속형 발화 매칭 ("~할게요", "~제출하겠습니다", "~까지 보내드립니다")
- 책임자 명시 안 된 경우 호스트 또는 발화자 본인을 기본값으로 추정 + 재확인 플래그
- 기한 명시 안 된 경우 "미팅일 + 7일" 기본값 + 재확인 플래그

---

## 5. 리스크·이슈 (Risks)

### 추출 룰
- "걱정", "리스크", "이슈", "문제", "어려움", "우려" 키워드 매칭
- 부정 표현 + 미래 시제 결합 시 리스크 후보 ("~하면 안 될 것 같아요", "~될 수도 있어요")
- 발화자가 명시적으로 부정한 사항 외에는 잠재 리스크로 분류

### 출력 형식
```
[리스크 1] 베뉴 가용일 충돌
  - 영향도: 상
  - 식별 발화: 고객사A 김부장 발화 32분경
  - 대응안: 6/18·6/25 양일 베뉴 사전 가예약, 6/12까지 확정

[리스크 2] 통역 인력 부족
  - 영향도: 중
  - 식별 발화: 호스트 발화 51분경
  - 대응안: 협력 통역사 명단 1주 내 확보
```

### 영향도 판정 기준
- **상**: 수주·계약 자체에 영향
- **중**: 운영 일정·예산에 영향
- **하**: 운영 효율성에 영향

---

## 6. 미결 사항 (Pending)

### 추출 룰
- "다음에", "검토해보고", "확인 후", "내부 협의 필요" 등 보류 시그널 발화 매칭
- 한쪽 제안만 있고 동의가 없는 항목 자동 분류
- 보류 사유 + 재논의 시점 함께 기록

### 출력 형식
```
[미결 1] 동시통역 부스 설치 여부
  - 보류 사유: 고객사A 본사 결재 필요
  - 재논의 시점: 다음 미팅 (5/16 예정)
  - 책임자: 고객사A 김부장

[미결 2] 사후 영상 콘텐츠 활용 권한
  - 보류 사유: 양측 법무 검토 필요
  - 재논의 시점: 계약 직전 단계
  - 책임자: 양측 법무
```

### 시리즈 모드 연동
- `--series` 모드 시 이전 회차 미결 사항을 "carry-over" 표시로 본 회의록 상단에 누적

---

## 7. 후속 일정 (Next Steps)

### 추출 룰
- "다음 미팅", "이후 일정", "다음 단계" 키워드 매칭
- 회의 마지막 10분 발화 비중 집중 분석
- 미정의 일정도 "추정" 표시로 기록

### 출력 형식
```
[다음 단계 1] 다음 미팅
  - 일자: 2026년 5월 16일(금) 14:00
  - 참석자: 본 미팅 동일 + 고객사A 본사 시니어 1인 추가 예정
  - 아젠다: 동시통역 결재 결과 + 베뉴 후보 답사

[다음 단계 2] 베뉴 답사
  - 일자: 2026년 5월 22일(목)
  - 참석자: 호스트 + 운영팀 + 고객사A 김부장
  - 아젠다: 그랜드하얏트 vs 페어몬트 현장 비교
```

### `--next-agenda` 옵션
- 활성화 시 별도 `next-agenda_[프로젝트]_[YYYYMMDD].md` 파일 산출
- 미결 사항 + 후속 일정을 다음 회차 어젠다 초안으로 변환

---

## 8. 전략 메모 (Strategy Notes) — 변별력 자산

**Internal 모드만 노출.** External 산출물에는 절대 포함되지 않음.

### 작성 원칙: 5W1H 전략 질문 템플릿

18년 경력 전략가의 시각으로 다음 6개 질문에 답하는 형식:

| 질문 | 핵심 |
|------|------|
| **Who** — 이 미팅이 누구에게 영향을 주는가? | 의사결정자·영향력자·반대자 식별 |
| **What** — 이 미팅의 진짜 안건은 무엇이었나? | 표면 안건 vs 실제 의도의 갭 |
| **When** — 이 미팅의 타이밍은 적절했나? | 너무 이른가 / 늦은가 / 적기인가 |
| **Where** — 이 미팅 결과가 어디까지 확산되나? | 의사결정 라인 매핑 |
| **Why** — 왜 지금 이 결정이 나왔나? | 명시 이유 vs 추정 이유 |
| **How** — 이 결과를 어떻게 활용할 것인가? | 다음 액션의 전략적 의미 |

### 출력 형식 예시
```
[전략 메모]

Who: 김부장이 의사결정자로 보이지만 실제 권한은 본사 시니어. 다음 미팅에서 본사 시니어 참석 시 그가 진짜 클라이언트.

What: 표면적으로는 행사 컨셉 협의였으나 실제로는 우리 운영 역량 검증 미팅. 1:1 미팅룸 비중 강조 = 영업 ROI 검증 의도.

When: 6월 행사 기준 5월 9일 미팅은 약간 빠듯. 본사 결재 일정 감안 시 5/16 미팅 후 베뉴 확정이 데드라인.

Where: 결정 라인은 김부장 → 본사 시니어 → 글로벌 본사. 한국 단독 결정 불가 사안이 다수.

Why: 고객사A가 한국 시장 본격 진출 시점. 행사 성과가 다음 분기 확장 결정의 근거가 됨.

How: 1:1 미팅룸 ROI 측정 지표를 사전 합의해야 다음 행사 수주 가능. 5/16 미팅에서 KPI 정의 안건 추가 권장.
```

### 자동 생성 vs 수기 보강
- 자동 생성 1차 시도 후 "초안" 표기 부착
- 기획자님이 수기 보강한 경우 "Final" 표기로 갱신
- 자동 생성 신뢰도 낮은 경우(transcript 정보 부족) "수기 작성 권장" 표시

## 8축 추출 우선순위

긴 transcript(1~2시간) 처리 시 청크 분할 후 다음 우선순위로 추출:

| 우선순위 | 축 | 이유 |
|---------|----|----|
| 1순위 | 결정사항 (3) | 회의록 핵심 가치 |
| 1순위 | Action Items (4) | 실무 추적 필수 |
| 2순위 | 미결 사항 (6) | 다음 회차 연결 |
| 2순위 | 후속 일정 (7) | 운영 일정 핵심 |
| 3순위 | 안건 (1) | 구조 형성 |
| 3순위 | 리스크·이슈 (5) | 운영 안정 |
| 4순위 | 발언 요지 (2) | 기록 보존 |
| 5순위 | 전략 메모 (8) | Internal 한정, 마지막 통합 단계 |

→ 시간 제약 시 1~2순위만 추출하는 `--quick` 모드 가능 (안건 + 결정 + Action + 미결 + 다음단계 5축).
