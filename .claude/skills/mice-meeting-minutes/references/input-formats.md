# Input Formats — 입력 포맷별 파서 사양

본 스킬은 다음 4개 채널의 입력을 표준 transcript 구조로 정규화한다.

---

## Channel 1 — 클로바노트 export (★ 권장 메인)

### 표준 export 포맷

```
참석자 1  00:00:12
안녕하세요, 오늘 미팅 시작하겠습니다.
오늘 다룰 안건은 세 가지입니다.

참석자 2  00:00:28
네, 자료 공유드릴게요.

참석자 1  00:01:05
첫 번째 안건부터 시작하겠습니다.
```

### 파싱 정규식

```
^(참석자 \d+|[가-힣]+\s?[가-힣]*)\s+(\d{2}:\d{2}:\d{2})$
```

### 처리 룰
- 화자 라인 식별 → 다음 빈 줄까지를 해당 화자 발화로 매핑
- 타임스탬프는 시리즈 모드 분석 메타데이터로 보관
- 한 화자가 연속 발화 시 통합

### 변별력 포인트
- 클로바노트는 한국어 STT 정확도·화자분리 강점
- 단점: 한·영 혼용 미팅에서 영어 인식 정확도 저하

### 클로바노트 export 추출 방법 (사용자 안내용)
1. 클로바노트 앱에서 미팅 선택
2. 우상단 메뉴 → "텍스트 내보내기"
3. .txt 파일 다운로드 또는 클립보드 복사
4. Claude 채팅창에 붙여넣기

## Channel 2A — Otter.ai export

### 표준 export 포맷

```
Lee Jincheol  00:00:12
Hello, let's start today's meeting.

John Kim  00:00:28
Sure, I'll share the documents.
```

### 파싱 정규식

```
^([A-Za-z][A-Za-z\s]+|[가-힣\s]+)\s+(\d{2}:\d{2}:\d{2})$
```

### 처리 룰
- 클로바노트와 거의 동일 — 화자 라벨 + 타임스탬프
- 영어 강점 → 영어 미팅·한·영 혼용 미팅에 권장

### Otter export 추출 방법
1. Otter 웹/앱에서 미팅 선택
2. Export → Plain text (.txt) 또는 SRT
3. 다운로드 후 Claude에 붙여넣기

## Channel 2B — Whisper (OpenAI) export

### 표준 export 포맷 (.txt)

```
[00:00:00 --> 00:00:05]  Hello, let's start today's meeting.
[00:00:05 --> 00:00:12]  Sure, I'll share the documents.
```

### 처리 룰 — 화자 정보 부재
- Whisper 기본 transcription은 **화자 분리 없음**
- 화자 분리는 Whisper + pyannote 조합 또는 별도 후처리 필요

### Whisper + pyannote 조합 시 포맷
```
SPEAKER_00 [00:00:00 --> 00:00:12]  Hello, let's start today's meeting.
SPEAKER_01 [00:00:12 --> 00:00:28]  Sure, I'll share the documents.
```

### 파싱 정규식

```
^(SPEAKER_\d+)\s+\[(\d{2}:\d{2}:\d{2})\s+-->\s+(\d{2}:\d{2}:\d{2})\]\s+(.+)$
```

### 변별력 포인트
- Whisper: 다국어 강점·로컬 실행 가능 → 보안 강한 미팅 권장
- 단점: 화자 분리 별도 후처리 필요, 한국어는 클로바노트보다 약함

## Channel 2C — Zoom transcript

### 표준 export 포맷 (.vtt)

```
WEBVTT

00:00:01.500 --> 00:00:05.000
Lee Jincheol: Hello, let's start today's meeting.

00:00:05.500 --> 00:00:12.000
John Kim: Sure, I'll share the documents.
```

### 파싱 룰
- VTT 형식: 타임스탬프 라인 + 발화자 prefix + 발화
- "이름: " prefix를 화자 라벨로 추출

### Zoom export 추출 방법
1. Zoom 미팅 종료 후 Cloud Recording 자동 생성
2. Zoom 웹 → Recordings → Audio Transcript 다운로드
3. .vtt 파일을 Claude에 붙여넣기

### 한계
- Zoom Pro/Business 이상 필요 (Free는 미지원)
- 자동 transcript 한국어 정확도 보통 (영어 권장)

## Channel 2D — Google Meet transcript

### 표준 export 포맷 (Google Docs)

```
참석자 - 회의 기록
2026년 5월 9일 14:00

호스트: 안녕하세요, 오늘 미팅 시작하겠습니다.

김부장: 네, 자료 공유드리겠습니다.
```

### 처리 룰
- Google Meet의 자동 회의 기록은 화자 라벨 포함
- 타임스탬프는 발화별로는 없고 미팅 전체 시간만
- Claude에 Google Docs 링크 직접 fetch 또는 텍스트 복사·붙여넣기

### Google Meet 추출 방법
1. Google Meet 미팅 중 "회의 기록" 활성화 (Workspace 계정 필요)
2. 미팅 종료 후 호스트 Drive에 Google Docs 생성
3. Docs 내용 복사 → Claude 붙여넣기

## Channel 2E — Microsoft Teams transcript

### 표준 export 포맷 (.docx 또는 .vtt)

```
[00:00:01] Lee Jincheol: 안녕하세요.
[00:00:05] John Kim: 네, 시작하겠습니다.
```

### 파싱 룰
- 타임스탬프 + 이름 + 콜론 + 발화 형식
- .docx export는 표 형식인 경우 있음 — 표 구조 우선 인식

### Teams 추출 방법
1. Teams 미팅 중 "녹음 시작" 활성화 (Transcription 자동)
2. 미팅 종료 후 미팅 채팅에 transcript 다운로드 링크 생성
3. .docx 또는 .vtt 다운로드 → Claude에 붙여넣기

## Channel 3 — 메모형 자유 텍스트

### 입력 예시

```
오늘 Darktrace 미팅 김부장이랑 했음
6월 18일 행사 확정
1일 컨퍼런스 + 1:1 미팅룸 50%/데모 50%
김부장이 ROI 강조 - 본사 보고용 필요
다음 미팅 5/16 본사 시니어 참석 예정
베뉴 답사 5/22 양측 동행
```

### 처리 룰
- 화자 라벨 부재 → 메모 작성자(호스트, 본 스킬 호출자)를 기본 화자로 추정
- "[이름]이/가 ~" 형태 발화 인용 시 해당 인물을 화자로 매핑
- 줄 단위로 안건·결정·Action 추정
- 신뢰도 낮음 → 8축 추출 후 사용자 확인 요청 빈도 높음

## Channel 4 — 채팅창 직접 구두 보고

사용자가 Claude 채팅창에 자유롭게 미팅 내용 구술.

### 입력 예시
```
"오늘 Darktrace 김부장이랑 미팅했는데, 6월 18일에 1일 컨퍼런스로 가기로
했어. 1:1 미팅룸이랑 데모 부스 반반. 본사 시니어가 5월 16일에 다음 미팅
참석할 예정이고, 베뉴 답사는 5/22에 같이 가기로 했어. 김부장이 ROI
강조했고 본사 결재 1.5억 라인이라 견적은 그 안쪽으로 가야 해.
회의록으로 만들어줘 type=A external client=darktrace"
```

### 처리 룰
- Channel 3과 동일 처리
- 단, 모드·유형 플래그가 메시지 내 명시되어 있으면 우선 적용
- 신뢰도 매우 낮음 → 거의 모든 추출 항목에 "(추정)" 표기

## 청크 분할 룰 (긴 transcript 처리)

### 분할 임계값
- 입력 길이 30분 미만: 단일 처리
- 30분 ~ 60분: 30분 단위 청크 2개
- 60분 ~ 120분: 30분 단위 청크 3~4개
- 120분 이상: 30분 단위 + 사용자에게 "분리 처리 권장" 안내

### 분할 방법

```
1. 타임스탬프 기반 분할 (Channel 1·2A·2B·2C·2E 우선)
   - 30분 마크에서 화자 발화 종료 지점까지 범위 잡기
   - 화자 발화 중간에서 자르지 않기

2. 토픽 기반 분할 (타임스탬프 없는 경우)
   - 안건 전환점 식별 → 그 지점 이전·이후 분리

3. 단순 분량 분할 (위 2가지 실패 시)
   - 전체 길이 N등분
```

### 청크별 추출 → 통합

```
[청크 1] → 8축 추출 → 부분 결과
[청크 2] → 8축 추출 → 부분 결과
[청크 N] → 8축 추출 → 부분 결과
       ↓
   통합 단계
       ├─ 결정사항: 시간순 정렬 + 중복 제거
       ├─ Action Items: ID 부여 후 통합 (중복 발화 통합)
       ├─ 미결 사항: 청크별 모음 + 중복 제거
       ├─ 안건: 토픽 그룹화
       ├─ 발언 요지: 안건별 통합
       ├─ 리스크: 모음 + 중복 제거
       ├─ 후속 일정: 시간순 정렬
       └─ 전략 메모: 전체 통합 후 1회 생성 (마지막 단계)
       ↓
   최종 회의록 산출물
```

## 화자 매핑 헬퍼

### 클로바노트 등의 익명 라벨 처리

기본 입력 (라벨이 익명):
```
참석자 1  00:00:12
안녕하세요, 오늘 미팅 시작하겠습니다.

참석자 2  00:00:28
네, 자료 공유드릴게요.
```

사용자가 매핑 입력:
```
참석자 1 = 호스트(PCO)
참석자 2 = 김부장 (Darktrace)
참석자 3 = 주대웅 실장 (리멤버)
```

→ 본 스킬이 모든 산출물(회의록·Action·요약)에서 익명 라벨을 실명·직함으로 자동 치환.

### 자동 추정 (사용자 매핑 미입력 시)

```
1. 발화 내용에 자기 호칭 시그널 매칭
   "제가 [이름]입니다" → 참석자 X = [이름]
   "Darktrace 김입니다" → 참석자 Y = 김부장 (Darktrace)
   
2. 호칭·직함 매칭
   "이 실장님" 발화 시 → 다른 참석자가 발화자를 "이 실장"으로 호칭
   
3. 사용자가 미팅 시작 시 참가자 명단을 본 스킬에 미리 알려준 경우
   → 발화 빈도·길이·내용으로 매핑 추정 + 신뢰도 점수
   
4. 자동 매핑 신뢰도 < 85% → 사용자 확인 요청
```

## Redaction 사전 처리

입력 단계에서 명백한 마스킹 필요 발화는 표시만 해두고 8축 추출 단계로 전달.

### 사전 표시 카테고리
- "[비공식]" 발화 시그널 ("솔직히", "오프 더 레코드")
- "[금액]" 비공식 예산 발화
- "[정치]" 비방·갈등 발화

→ 8축 추출 시 카테고리 표시를 참고하여 redaction-rules.md 룰 적용.

## 입력 검증 체크리스트

`parse_input.py` 실행 직후 자동 검증:

| 체크 | 기준 | 미달 시 |
|------|------|--------|
| 입력 길이 | 100자 이상 | "입력이 너무 짧음 — 추가 정보 권장" |
| 화자 분리 | 2명 이상 발화 식별 | "단일 화자 transcript — 메모형 처리로 전환" |
| 발화 분포 | 한 화자 80% 미만 | "발화 비율 편중 — Type B 단방향 보고일 가능성" |
| 타임스탬프 | Channel 1·2 형식 일치 | "타임스탬프 미인식 — 메모형 처리로 fallback" |
| 한·영 혼용도 | 한국어 70% 이상 권장 | "한·영 혼용 — Otter·Whisper 권장 안내" |
