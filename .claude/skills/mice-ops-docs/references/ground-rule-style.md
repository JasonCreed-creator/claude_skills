# 팀 지침 · 그라운드룰 · 프로토콜 매뉴얼

마켓데이터사업실(마데실) Ground Rule 문서의 문체와 구조. Slack 캔버스로 옮길 때의 방언·서식은 `mice-slack-ops/references/canvas-rules.md`가 정본이고, 본 문서는 본문 작성 규칙만 정한다.

> **Ground Rule 문체 정본 = 본 문서 §2.** `mice-slack-ops`(SKILL·`canvas-rules.md`)는 문체를 다시 적지 않고 이 절을 포인터로 참조하며, 캔버스 방언(헤딩 번호·콜아웃·멘션)만 정한다. 문체를 고칠 때는 여기만 고친다.

---

## 1. 범위 3층

지침이 다루는 것은 세 가지뿐이다.

1. 소통 구조 — 채널 · 스레드 · 회의 · 보고 경로
2. MICE비즈팀이 하는 일과 기한
3. 인터페이스 — 다른 팀에서 받는 것 / 넘기는 것

다른 팀의 SLA·양식·순서는 쓰지 않는다. 필요한 자리에는 "각 팀 기준을 따른다"만 둔다.

## 2. 문체

- 개조식 중첩 불릿. 명사형 종결("재택 표시 필수", "회신 의무는 없음").
- 원칙·배경을 설명하는 문장만 합니다체. ~요체 금지.
- 근거는 괄호로 짧게("(9/17 결정)").
- 이모지는 대·중분류 헤더에만, 본문 금지.
- 날짜는 `M/D(요일)`, 기한은 굵게.
- 예외는 "단,"으로 시작하는 한 줄로 붙인다(본문 규칙 뒤).
- "반드시"는 아껴 쓴다 — 위반 시 실제 불이익이 있는 항목에만.

### 예

```
## 2. 스레드 운영
- 1행사 = 1스레드
  - 최상위 게시는 견적문의 봇만 허용
  - 같은 고객의 N회차·재계약은 새 스레드
- 상태 보드는 첫 댓글
  - MICE PM이 수정하며 관리
  - 단계 전환은 한 줄 댓글(`[S5 시작] …`)
스레드는 행사 하나의 처음과 끝을 한곳에 남기기 위한 장치입니다.
```

## 3. 매뉴얼 구조

1. 목적 (1~2문장, 합니다체)
2. 적용 범위 · 시행일
3. 규칙 본문 (번호 섹션, 중첩 불릿)
4. 템플릿 (코드 블록)
5. FAQ (질문은 실제로 받은 것만)
6. 정본 링크 · 문의처

## 4. 최종본 원칙

- 공표본에는 최종 규칙만. 근거·진단·결정 사유·레드팀 메모·변경 이력은 내부 작업 md로 분리.
- 캔버스 게시·채널 공유는 사용자가 직접 한다. 본 스킬은 본문까지.
