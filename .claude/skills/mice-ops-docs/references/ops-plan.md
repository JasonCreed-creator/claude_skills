# 운영계획서 — 골격 · 입력 매핑 · 표 양식

확정된 행사를 실제로 굴리는 실행 계획. 현장 R&R·타임라인·리스크 대응이 핵심이다.

**7섹션 골격의 정본은 본 문서 §2**다(입력 매핑 §1·표 양식 §3·마감 점검 §4 포함). `jc-doc-coauthor`는 이 골격을 링크로 참조해 섹션별 공동 집필만 한다 — "같이 쓰자"·"섹션별로 묻고 가자" 신호가 있으면 그 스킬, 바로 문서가 필요하면 본 스킬. 골격을 고칠 때는 여기만 고친다.

---

## 1. 입력 매핑

| 입력 | 어디서 | 채우는 섹션 |
|------|--------|-------------|
| 행사 개요(행사명·일시·장소·규모·목표) | 계약완료 메시지(`mice-slack-ops/references/contract-message.md`) · 스레드 상태 보드 | 1 |
| 킥오프 결정·Action·담당 | `mice-meeting-minutes` ChainPayload · 회의록 | 2 · 3 · 7 |
| 큐시트(당일 세그먼트) | `mice-run-of-show` ChainPayload `plan.cues` | 3 (D-day 상세) |
| 예산·벤더 범위 | `mice-estimate` 산출 | 5 |
| 모객 목표(쇼업·리드) | 계약완료 메시지 `목표` | 1 · KPI |

없는 값은 `[미확보]` + 문서 끝 "확인 필요" 목록. 추론으로 채운 값은 `(가정)` 표기.

## 2. 7섹션 골격

1. **운영 개요** — 행사 요약 표(행사 ID · 행사명 · 일시 KST · 장소 · 규모 · 목표 쇼업/리드 · 발주처 담당) + 운영 범위(우리 일 / 발주처 일 / 협력사 일 3열).
2. **운영 조직·R&R** — 의사결정 라인을 먼저. 총괄 → 파트(등록·세션·F&B·VIP·연출·제작물) → 담당. 현장 무전 채널·연락 체계.
3. **상세 타임라인** — D-day 역산 임계 경로(D-30·D-14·D-7·D-3·D-1·D-day·D+5). D-day는 큐시트 요약 + 원본 링크.
4. **구역·동선 계획** — 등록 · 세션장 · F&B · VIP · 전시/부스. 도면 링크, 피크 시간대 동선.
5. **협력사·벤더 운영** — 업체 · 범위 · 계약 상태 · 현장 책임자 · 백업 수단.
6. **리스크·비상 대응** — 시나리오별 대응 매트릭스.
7. **체크리스트** — 사전 / 현장 / 철수. 그룹당 8개 이내.
