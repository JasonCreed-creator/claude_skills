# MICE 제안서 자동 생성 스킬 (v2.1.1)

## 개요

RFP(제안요청서) 또는 비딩 공고 문서를 분석하여, MICE 행사 제안서를 PPTX 프레젠테이션으로 자동 생성한다. 전시회·박람회를 1순위로 최적화하되, 컨퍼런스·포럼·기업행사 등 전체 MICE 유형을 커버한다.

### 버전 히스토리
- **v1.0 (2026-04)**: 초기 7섹션 표준 구조
- **v2.0 (2026-05-25)**: 비주얼 패턴 시스템 도입 (이미지 6종 + 표 4종 + 차트 3종 + 다이어그램 4종)
- **v2.1 (2026-05-25)**: 5개 확장 모듈 추가 — 인포그래픽(퍼널·매트릭스·레이더), 다크 모드, 아이콘 라이브러리, 슬라이드 마스터(네이티브 그림 자리표시자), jc-design-system 토큰 연동
- **v2.1.1 (2026-06-04)**: frontmatter `version` 필드 신설 (v2.1.1) — 다운스트림 pt-script·mice-meeting-minutes가 이미 참조하던 버전과 정합화. 기능 변경 없음.

## 워크플로우

### Phase 1: RFP 분석

사용자가 업로드한 RFP/비딩 문서에서 다음 핵심 정보를 추출한다:

| 추출 항목 | 설명 |
|-----------|------|
| 행사명 | 정식 명칭 및 부제 |
| 발주처 | 주최·주관 기관명 |
| 행사 유형 | 전시회, 박람회, 컨퍼런스, 포럼, 기업행사 등 |
| 일시/장소 | 개최 일정 및 베뉴 |
| 규모 | 참가자 수, 부스 수, 전시면적 등 |
| 예산 범위 | 총 예산 또는 항목별 예산 |
| 평가 기준 | 배점 기준표 (기술, 가격, 실적 등) |
| 핵심 요구사항 | RFP에 명시된 필수 이행 조건 |
| 제출 조건 | 페이지 제한, 제출 양식, 마감일 등 |

추출 완료 후 사용자에게 **분석 요약**을 제시하고 확인을 받는다.

### Phase 2: 제안서 구조 설계

RFP 분석 결과를 바탕으로 슬라이드 구성안(목차)을 설계한다.

### Phase 2.5 (v2.1 신규): 모드 결정

사용자에게 다음 4가지 결정을 묻는다:

#### 결정 1. 컬러 모드
- **[A] RFP 컬러 모드** — RFP에 발주처 CI가 명시된 경우. 공공/정부 발주 시 권장.
- **[B] JC 시그니처 모드** (기본 권장) — jc-design-system의 Deep Navy + Electric Blue. 일관된 개인 브랜드.
- **[C] JC + 클라이언트 오버레이 모드** — JC 베이스 + 클라이언트별 accent 컬러. 협업 행사(리멤버 등) 권장.

#### 결정 2. 이미지 자리 처리 방식

> 이미지 에셋은 jc-design-system의 RULE-VISUAL-ROUTING을 따른다 (사진/래스터=Higgsfield, 표·다이어그램·차트=Claude 자체).

- **[A] 회색 박스 모드** (기본 권장) — 회색 점선 박스 + 캡션. 즉시 확인 용이.
- **[B] 마스터 모드** — PowerPoint 네이티브 그림 자리표시자. 우클릭으로 그림 변경 가능.
- **[A+B] 혼합 모드** (권장) — 표지·섹션구분·Thank You는 마스터, 본문은 회색 박스.

#### 결정 3. 다크 모드 사용
- **[A] 최소** — 표지·섹션구분·Thank You만 다크 (8장, 기본 권장)
- **[B] 강조** — 기본 8장 + 기대 효과·KPI 대시보드 추가 다크 (10장)
- **[C] 없음** — 전부 라이트 모드 (단순한 사내 검토용)

#### 결정 4. 아이콘 라이브러리
- **[A] Heroicons 사용** (기본 권장) — 모던, 일관성
- **[B] Font Awesome 사용** — MICE 특화 아이콘 풍부
- **[C] 아이콘 없이 텍스트만** — 빠른 생성

### Phase 3: 슬라이드 생성

**다음 6개 파일을 반드시 모두 읽고 시작한다:**

1. `references/slide-structure.md` — 섹션별 슬라이드 + 패턴 코드 매핑

6. `references/slide-masters.md` — 슬라이드 마스터 + 네이티브 그림 자리표시자 (마스터 모드 선택 시)

PPTX 생성은 반드시 `/mnt/skills/public/pptx/SKILL.md` 및 `/mnt/skills/public/pptx/pptxgenjs.md`의 가이드를 따른다.

## 표준 섹션 구조

제안서는 아래 7개 섹션, 총 50페이지 이내로 구성한다.

| 섹션 | 슬라이드 수 | 핵심 패턴 |
|------|-----------|----------|
| 1. 표지 및 목차 | 2~3 | `IMG-HERO`, `MASTER-TITLE` |
| 2. 행사 개요 및 컨셉 | 5~8 | `INFO-I2` (포지셔닝), `CHART-C3+ICON` (효과), `TBL-T2` (대응표) |
| 3. 운영 계획 | 10~15 | `DIAG-D1` (조직도), `DIAG-D3` (타임라인), `TBL-T3` (일정), `INFO-I1` (모객 퍼널) |
| 4. 크리에이티브 | 3~5 | `IMG-MOOD`, `IMG-WIDE` |
| 5. KPI/성과관리 | 3~5 | `CHART-C3+ICON`, `CHART-C1`, `TBL-T2` |
| 6. 회사 소개/레퍼런스 | 5~8 | `INFO-I3` (역량 레이더), `DIAG-D4+ICON`, `IMG-AVATAR` |
| 7. 예산/부록 | 3~5 | `TBL-T4`, `CHART-C1`, `MASTER-THANK_YOU` |

상세 슬라이드별 패턴 매핑은 `references/slide-structure.md` 참조.

## 이미지 자리 처리 — 두 가지 방식 비교

| 방식 | 설명 | 적합한 경우 |
|------|------|-----------|
| **회색 박스 모드** | 회색 점선 박스 + 캡션 + 노트 안내 | 일반 제안서, 즉시 검토 필요 |
| **마스터 모드** | PowerPoint 네이티브 그림 자리표시자 (`type: "pic"`) | 발주처가 PowerPoint에서 직접 이미지 교체할 가능성, 반복 사용 템플릿 |
| **혼합 모드** (권장) | 강조 슬라이드(표지·섹션구분·Thank You) = 마스터, 본문 = 회색 박스 | 균형, 시각 강조 + 본문 유연성 |

자세한 마스터 정의는 `references/slide-masters.md` 참조.

## 실행 순서 요약

```
1. RFP 문서 읽기 → 핵심 정보 추출
2. 사용자에게 분석 요약 제시 → 확인/보완
3. 슬라이드 구성안(목차 + 패턴 매핑) 제시 → 사용자 확인
4. [v2.1 신규] Phase 2.5 — 4가지 모드 결정
   - 컬러 모드 (RFP / JC / JC+오버레이)
   - 이미지 자리 처리 (회색 박스 / 마스터 / 혼합)
   - 다크 모드 (최소 / 강조 / 없음)
   - 아이콘 (Heroicons / Font Awesome / 없음)
5. 필요한 references 파일 모두 읽기 (모드에 따라 3~6개)
6. /mnt/skills/public/pptx/SKILL.md 및 pptxgenjs.md 읽기
7. 컬러 모드가 B/C인 경우 jc-design-system 토큰 파일 읽기
8. 행사 유형에 맞춰 섹션 비중 조절
9. PPTX 생성 (LAYOUT_WIDE 고정, Pretendard 폰트, 결정된 모드 일관 적용)
10. 슬라이드 노트에 이미지 placeholder 교체 안내 + 폰트 안내 자동 삽입
11. QA 수행 (콘텐츠 + Visual QA 서브에이전트)
12. 최종 파일 전달
```

**중요**: 각 단계에서 사용자의 확인을 받은 후 다음 단계로 진행한다. 특히 Phase 1, 2, 2.5 이후에는 반드시 사용자 승인을 받는다.
