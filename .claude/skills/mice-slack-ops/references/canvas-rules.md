# 캔버스 · 메시지 작성 규칙

2026-09-17 "구글독으로 만들어 주자 ugly" 피드백 이후 확정된 규칙. 캔버스는 `slack_create_canvas` 고유 마크다운 방언을 쓴다(메시지 서식과 다르다).

---

## 1. 무엇을 캔버스로 만드나

- 사내 공표·프로토콜·가이드·오픈 건 현황처럼 Slack 안에서 바로 읽혀야 하는 것.
- 구글독은 사용자가 요청할 때만(정본 보관용). 구글독과 캔버스를 병행하면 캔버스는 "매뉴얼 사본"임을 헤더에 적고 동기화 책임을 정한다.
- 캔버스에는 최종본만. 작업 산출물(근거·스펙·레드팀 메모)은 로컬 md·내부 작업문서로.

## 2. 구조 규칙

- **표는 3~5열, 셀은 짧게.** 8열 RACI·긴 셀 텍스트는 단계별 행이나 불릿으로 축약. ASCII 흐름도 금지.
- **핵심 원칙·경고는 콜아웃** `::: {.callout}` … `:::`.
- **이관 계획·미결·할 일은 체크리스트** `- [ ]`. 체크리스트 항목에 `1.` 숫자 접두를 쓰면 중첩 목록으로 깨짐 → `**1**` 굵은 숫자.
- **채널 멘션** `![](#C0AH445N61K)`, 유저 `![](@U…)`. 읽기 도구는 `<#C…>` `<@U…>`로 되돌려 보여준다(정상).
- **템플릿은 최상위 코드블록**(들여쓰기 안에 넣으면 깨짐).
- 결정 필요 표시는 한 가지로 통일. `:grey_question:3`처럼 이모지 코드 바로 뒤에 숫자를 붙이면 텍스트로 남음 → 유니코드 `❔` 사용. 최종본에서는 모두 제거.
- 헤더는 `#`/`##`, 인라인 코드는 최소화(`[결정 필요]` 남발 금지).
- 본문 인라인 표기 `[S5 시작]` 같은 태그는 코드가 아닌 굵게.

## 3. 캔버스 갱신 절차

1. `slack_read_canvas`로 현재 본문 확보 → 바꿀 절만 식별.
2. 로컬 md 정본(있으면)을 먼저 고치고 같은 내용을 캔버스에 반영.
3. `slack_update_canvas`는 사용자 승인 후. 갱신 후 `slack_read_canvas`로 재확인(멘션·표 깨짐).
4. 채널 공유(게시)는 사용자가 직접(9/21 그라운드룰 사례).

## 4. 문체

- 지침·매뉴얼 캔버스: 마데실 Ground Rule 문체 — 개조식 중첩 불릿(명사형 종결: "재택 표시 필수", "회신 의무는 없음"), 원칙·배경 문장만 합니다체, 근거는 괄호, 예외는 "단,", "반드시"는 아껴서. ~요/~해요 금지. 헤딩 번호 "1.1." 형식. 실 룰과 같은 항목은 "(실 룰 동일)".
- 공지·안내 캔버스: 합니다체, 첫 줄 결론, 대상·시행일·문의처 명시.

## 5. 메시지 서식 (slack_send_message 계열)

- 표준 마크다운(`**굵게**`, `- 불릿`, `> 인용`, 코드블록, 표). 레거시 mrkdwn(`*굵게*`) 금지. 요소당 ~5000자.
- 첫 줄에 결론(모바일·알림에서 첫 줄만 보임). 1~3문단. 3개 이상은 불릿. 이름·날짜·기한·액션은 굵게.
- 특정 메시지에 답할 때는 스레드. 전체가 봐야 하면 `reply_broadcast`. 새 주제·공지·전체 질문만 채널 최상위.
- 인라인 이미지는 링크로만 렌더 → 이미지가 필요하면 캔버스.
- 발송 전 초안을 보여주고 승인 받는다. 예약 발송은 `slack_schedule_message`.
