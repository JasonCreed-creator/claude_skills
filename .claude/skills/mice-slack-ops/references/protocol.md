## 1. 채널 규칙

- `#mice_운영요청` 최상위 게시 = `MICE 견적문의`(행사운영 요청) 봇뿐. 타깃논의·계약·킥오프·제작·모객·현장·사후·정산은 전부 해당 행사 스레드.
- `#mice비즈팀-문의` 폐지. `#mice-biz-team`은 팀 내부(행사 결정은 행사 스레드에 기록).
- MICE PM이 고객 채널(Slack Connect·조인트·카톡·메일·유선)에서 합의한 내용은 **당일** 스레드에 요약.
- 타깃논의·계약완료가 실수로 최상위에 오면 MICE비즈팀이 해당 스레드에서 다시 실행하도록 안내.

## 2. 단계 S1~S7

| 단계 | 스레드에 남는 것 | MICE비즈팀이 하는 일 |
|------|------------------|----------------------|
| S1 행사 요청 = 스레드 생성 | 견적문의 게시 · 상태 보드(첫 댓글) · 견적 회신 댓글 | MICE PM 배정 · 상태 보드 생성 · 견적 |
| S2 타깃논의(선택) | 타깃논의 답글 · 타깃 회신 | 필요 시 실행 · 결과를 상태 보드에 반영 |
| S3 제안·협상 | 고객 전달 · 재견적 · 미팅 노트 · 컨펌 | 재견적 · 변경 반영 |
| S4 계약완료 | 계약완료 답글 · 담당 배정 · 매관시 ID | 상태 보드 갱신 · 트래커·폴더 · 킥오프 조율 |
| S5 킥오프·준비 | 회의록 · WBS · 운영계획서 v1 · 추가 견적 | 킥오프 주관 · WBS · 운영계획서 · 베뉴·제작물 착수 |
| S6 모객·제작 | 모객 현황 · 제작 진행 · D-7 최종 운영계획 | 제작물 · 베뉴 · F&B · 인력 확정 |
| S7 현장·사후 | 현장 리포트 · 결과보고서 · 정산 · 종료 요약 | 현장 총괄 · 결과보고서 · 정산 · 종료 요약 |

세부: S1은 모수 확인만 필요해도 봇으로 스레드를 먼저 연다(견적 유형 「모수 확인 먼저」). 계약 전 킥오프는 `[킥오프 요청]` 댓글 → 팀장 승인. 실주·보류·전환은 사유와 함께 상태 보드에 기록. 전달 후 10영업일 무변동이면 MICE PM이 진행 여부 확인.

## 3. MICE비즈팀 약속 기한

| 단계 | 약속 |
|------|------|
| S1 | MICE PM 배정 업무시간 4시간 · 견적 A(모객 only) 1영업일 / B(모객+운영 가견적) 2영업일 / C(베뉴 확정 상세) 3~5영업일(지연 시 중간 공유) |
| S3 | 재견적 = S1과 동일 |
| S4 | 상태 보드 즉시 · 트래커·캘린더·폴더 2영업일 · 계약 후 5영업일 내 킥오프 미팅 실시 목표 |
| S5 | 회의록 당일 · WBS 킥오프 +3영업일 · 운영계획서 v1 모객 오픈 전 |
| S6 | D-7 최종 운영계획 확정·공유 |
| S7 | 현장 리포트 당일 · 결과보고서 5영업일 |
| 공통 | 고객 합의 당일 기록 · 상태 보드는 단계 전환 시와 매주 월요일 갱신 · 긴급(24시간 내 회신 기한)은 4시간 내 "가능/불가+대안" |

"5영업일 내 개최" 같은 표현은 행사 개최로 오독됨 → "킥오프 미팅 실시"로 명시.

## 4. 스레드 규칙

- **행사 ID** `YYMMDD_고객사_행사명`(행사일 기준, 미정 `YYMM00`). 게시 제목 · 상태 보드 · 드라이브 폴더 · WBS 제목 · 매관시 비고 · 트래커 · 캘린더에 동일 사용.
- **상태 보드** = 첫 댓글, MICE PM이 수정(새 댓글 금지). A to Z 스레드의 목차. 마일스톤 댓글 링크를 모아둔다.
- **단계 전환 댓글** `[S5 시작] 킥오프 9/23 완료, WBS 착수`. `[S5`로 검색.
- **접두 태그** `[결정]` `[견적변경]` `[킥오프]` `[WBS]` `[제작]` `[키비주얼]` `[베뉴]` `[현장]` `[결과보고]` `[정산]` `[종료]`. 결정은 무엇을·누가·언제 한 줄.
- **파일 대신 드라이브 링크.** S4에서 표준 폴더: `MICE / 2026 / [행사 ID] / 01_견적 · 02_계약 · 03_제작·키비주얼 · 04_WBS·운영계획 · 05_현장 · 06_결과보고·정산`.
- 키비주얼은 MICE PM이 브랜드디자인팀에 의뢰·일정 관리, 고객 컨펌은 영업 경유. 제작물은 확정 키비주얼·제작요청서 기준 착수.

## 6. 예외 FAQ (요지)

- 타깃논의만 먼저 → 봇으로 스레드 먼저 열고 그 안에서 실행.
- 중복 요청 → 나중 게시물에 기존 링크 달고 닫음.
- 봇을 최상위에 잘못 올림 → 삭제 후 최상위 메시지에서 재실행.
- 스레드가 길다 → 상태 보드가 목차, 단계 태그 검색, 끝난 사람은 팔로우 해제.
- 다회차 계약 → 회차마다 스레드, 계약완료는 1차에 게시 + 링크. 재계약·N회차 → 새 스레드.
- DMS 스폰서십 → 스폰서별 스레드 하나씩, 행사 유형 「스폰서십」. 모객 없는 대행 → 「대행 전용」.
- 취소·연기 → 사유·일자 기록 후 `[종료]`/`[보류]`. 리드젠 서베이 전환 → 전환 사실·링크 남기고 마무리.
- Slack Connect → 대외용 개설 가능, 내부 결정은 행사 스레드.
