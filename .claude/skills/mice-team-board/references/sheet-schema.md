# 시트 구조 — 탭 · 열 · 메뉴

> "실측 필요" 표시는 2026-10-05 스킬 작성 시 보드 원본을 열어 확인하지 못한 항목이다. 첫 실사용 때 시트를 읽어 이 문서를 고치고 버전을 올린다(`jc-skill-forge` 모드 C).

---

## 1. 탭

| 탭 | 단위 | 용도 |
|----|------|------|
| 프로젝트 | 1행 = 1프로젝트(운영요청) | 기본 정보·상태·금액 |
| 배정 | 1행 = 1인 × 1프로젝트 × 역할 | M/D 배정, 가동률 집계 원천 |
| 마일스톤 | 1행 = 1마일스톤 | 표준 마일스톤 세트 + 완료일·담당 |
| 정산 | 1행 = 1정산 항목 | 정산 진행·마감 (열 구성 실측 필요) |

트래커 = 팀 보드 프로젝트 탭. 프로젝트 등록 시 [성사] 알림은 Slack 팀 내부 채널에 자동 게시된다(용어·채널은 `mice-slack-ops/references/channels.md` §1·§4). 행사 내부 업무 체크리스트(대기/진행/보류/완료)는 팀 보드가 아니라 행사 드라이브의 체크리스트 시트 — `mice-ops-docs/references/drive-standards.md` §5.

## 2. 프로젝트 탭 (A~P) — 열 정의 정본

이 표가 정본이다. 계약완료 메시지 필드 → payload 키 매핑은 `mice-slack-ops/references/contract-message.md` §3, 행 값 표 생성은 `scripts/board_rows.py`(괄호 안 = `contract` 키).

| 열 | 필드 | 형식 · 계약완료 등록 값 |
|----|------|------|
| A | 프로젝트ID | `P-YYYY-NNN`. 신규는 메뉴 "프로젝트 ID 채우기" 또는 수기, 갱신은 `matched_row` |
| B | 행사명 | 계약완료 `주제`(`title`) |
| C | 발주처 | 고객사(`client`) |
| D | 유형 | ① 리멤버 MICE 솔루션(모객+운영) ② 일반 행사(게런티 없음) ③ DMS·주최형 ④ 커스터마이즈(`type`) |
| E | 상태 | 견적 · 계약 · 준비 · 진행 · 완료 · 정산완료 · 드롭. 신규 등록은 `계약`(착수하면 `준비`), 갱신은 `status_hint`가 `계약`·`준비`일 때만 |
| F~J | 일정 | F 행사일(KST, `event_at_kst`). G~J 세부 일정(설치일 등 — 비고에 있으면) 열 이름 실측 필요 |
| K | 베뉴 | 행사장소(`venue`) |
| L | 게런티 | 목표 쇼업 수(`guarantee`) |
| M | 예상 참가 | 별도 없으면 L과 동일 |
| N | 계약금액 | 계약 매출, 원, VAT 별도, 숫자만(`revenue`) |
| O | 비고 | 결제 조건 · PO/계약서 형태 · 리드 수 · 타깃 조건 요지 · 재계약ID · 아이템ID · 인입채널 · 운영 Cell — payload `notes` 완성 문자열 그대로 |
| P | 등록일 | YYYY-MM-DD(등록한 날) |

## 3. 배정 · 마일스톤 탭

- 배정 기본 행: 영업 담당 3 M/D(역할 = 영업). MICE PM은 배정 확정 후 추가.
- 마일스톤 첫 항목: "계약 체결" — 완료일 = 메시지 날짜(실제 체결일이 없으면), 담당 = 영업.
- 두 탭의 정확한 열 순서와 표준 마일스톤 전체 목록은 실측 필요. 메뉴 "표준 마일스톤 생성"이 만드는 세트를 그대로 따른다.
