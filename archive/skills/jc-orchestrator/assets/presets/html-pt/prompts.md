# html-pt 표준 프롬프트 3종

v1의 prompts/ 3파일(사용자 킥오프·에이전트 호출·Phase 승인)을 통합 재생성. 실제 사용 시 `< >` 를 채워 쓴다.

## §1. 사용자 킥오프 프롬프트

```
[html-pt 팀 가동]
프로젝트: <행사/비딩명>
입력: inputs/ 에 <RFP·브리프 파일명> 업로드 완료
모드: <풀(8) / 경량(4 — README 기준)>
분량: <N장 내외> / 발표 시간: <M분> / 청중: <의사결정자 유형>
클라이언트 오버레이: <지정 / 미지정(jc 시그니처)>
쓰기 경계: outputs/ 는 에이전트 산출 전용, inputs/ 는 읽기 전용
커밋 권한: <메인만 / 해당 없음>
완료 신호: PROGRESS.md 1줄 로그
Phase 경계마다 승인 받고 진행할 것.
```

## §2. 에이전트 호출 표준 (메인 → 서브에이전트, 매 호출 적용)

```
[에이전트: <slug>]
입력: 다음 파일을 반드시 읽고 시작 — <outputs/NN-*.md 경로 열거>
과업: 출력 계약(에이전트 정의 §4)의 산출물 1개
출력: outputs/<NN-slug-요지.확장자> 에 저장
완료 보고: 산출 경로 + 핵심 결정 3줄 + 미해결 이슈
주의: 계약 밖 파일 쓰기 금지 / 산출 불가 시 중단 보고(사유+시도+대안 1개)
```

- 입력 경로 열거는 **생략 불가** — 서브에이전트는 메인 대화를 보지 못한다(컨텍스트 격리).

## §3. Phase 승인 응답 패턴 (사용자 → 메인)

| 의도 | 표준 응답 | 메인 동작 |
|------|----------|----------|
| 승인·진행 | "Phase <N> 승인, 다음 진행" | 다음 Phase 에이전트 호출 |
| 부분 수정 | "승인 전 수정: <슬라이드·항목 지정>" | 담당 에이전트만 재호출 후 재제시 |
| 재작업 | "Phase <N> 재작업: <사유>" | 해당 Phase 입력부터 재실행 |
| 위임 | "추천안으로 진행" | 메인이 판정·기록 후 진행 |

- 승인 없이 Phase를 넘기지 않는다. 승인 기록은 PROGRESS.md에 1줄 남긴다.
