# 에이전트 카탈로그 — 8 아키타입 상세 스펙

각 아키타입은 팀 구성 시 조합하는 **역할 원형**이다. 프로젝트별 에이전트는 아키타입을 기반으로 [`../assets/agent-template.md`](../assets/agent-template.md) 템플릿에 맞춰 구체화한다. 연결 스킬은 해당 아키타입이 산출물을 낼 때 우선 라우팅하는 전용 스킬이다(각 SKILL description이 세부 매핑의 SoT).

---

## 1. 전략기획 — strategist

- **역할**: 목표·논리 골격 설계. "왜 이 순서·이 구조가 목적을 달성하는가"를 결정
- **연결 스킬**: jc-strategy-canvas(프레임워크 구조화) · mice-rfp-analyzer(RFP 7축 분석)
- **입력 계약**: 브리프(목표·제약·성공 기준) / RFP·공고 / 선행 리서치 산출물
- **출력 계약**: 전략 아웃라인·GO/NO-GO 판정·스토리라인 (md)
- **페어링 주의**: 리서치 산출을 입력으로 받는 경우가 많아 대개 리서처 뒤 또는 병렬 배치. 팀의 최상류 — 이 산출이 흔들리면 하류 전체 재작업

## 2. 리서치 — researcher

- **역할**: 외부 근거 수집. 시장·경쟁·벤치마크·발주처 데이터를 출처와 함께 확보
- **연결 스킬**: mice-market-intel(MICE 도메인 구조화 리서치) · 웹검색/딥리서치(범용)
- **입력 계약**: 조사 항목 리스트(전략기획 또는 브리프에서 도출)
- **출력 계약**: 출처 표기 리서치 리포트 (md) — 팩트/추론/가정 3분류 준수
- **페어링 주의**: 독립 실행 가능 → 병렬 배치 1순위 후보. 산출은 반드시 파일로 남겨 하류가 경로로 참조

## 3. 콘텐츠 — content

- **역할**: 산문·카피·스크립트 저작. 구조화된 골격을 읽는 글로 전환
- **연결 스킬**: jc-doc-coauthor(공동 작성 프로세스) · jc-comms(커뮤니케이션 글) · pt-script(발표 대본)
- **입력 계약**: 전략 아웃라인 + 리서치 근거 (경로 명시 필수)
- **출력 계약**: 문서·카피 초안 (md/docx)
- **페어링 주의**: 전략기획 산출에 강의존 → 순차 배치. 디자인과는 병렬 가능(콘텐츠↔디자인은 서로 독립 입력)

## 4. 디자인 — designer

- **역할**: 시각 정체성·토큰 적용. 산출물에 일관된 룩을 부여
- **연결 스킬**: jc-design-system(토큰 SoT) · jc-theme-factory(테마·오버레이 선택) · jc-visual-philosophy(키비주얼) · jc-brand-styling(후처리 적용)
- **입력 계약**: 산출물 파일 + 적용할 오버레이 지정(미지정=jc 시그니처)
- **출력 계약**: 토큰 적용본·키비주얼 (파일 형식은 원본 따름)
- **페어링 주의**: **토큰 값 하드코딩 금지** — 반드시 jc-design-system 런타임 로드. UI/UX 빌더와 순차 권장(디자인 → 빌드 반영)

## 5. UI/UX — builder

- **역할**: 인터랙티브 산출물 구현. 페이지·앱·코드아트를 동작하는 형태로
- **연결 스킬**: jc-landing-page(LP) · jc-artifact-builder(React 아티팩트) · jc-generative-art(p5.js)
- **입력 계약**: 콘텐츠 확정본 + 디자인 토큰·테마 지정
- **출력 계약**: 단일 HTML/아티팩트 (자가완결 파일)
- **페어링 주의**: 콘텐츠·디자인 확정 후 착수(순차). 미확정 상태 착수는 재빌드 비용이 가장 큰 지점

## 6. 데이터분석 — analyst

- **역할**: 수치·구조화 데이터 처리. 견적·KPI·통계를 판단 가능한 형태로
- **연결 스킬**: mice-dashboard(KPI 대시보드) · mice-estimate(견적 엔진) · xlsx(시트 가공)
- **입력 계약**: 원천 데이터 파일(xlsx/csv) 또는 ChainPayload/v1 봉투
- **출력 계약**: 대시보드 HTML·견적 xlsx·분석 시트 + (하류 체이닝 시) ChainPayload/v1
- **페어링 주의**: 독립 실행 가능 → 병렬 후보. 구조화 데이터 핸드오프는 반드시 봉투 규약

## 7. 코드 — engineer

- **역할**: 개발·빌드·QA·시스템 연동. 스크립트와 파이프라인 담당
- **연결 스킬**: (Code 서피스 네이티브 — 전용 스킬 없음) · jc-mcp-builder(외부 연동 서버)
- **입력 계약**: 스펙 문서 + 레포/작업 폴더 접근 경계
- **출력 계약**: 동작 검증된 코드·빌드 결과 + 검증 로그
- **페어링 주의**: 쓰기 경계·커밋 권한을 킥오프에 반드시 명문화(병렬 세션 충돌 방지 정본 규칙)

## 8. 리스크 — reviewer

- **역할**: 완성물 적대적 검증. 결함·허점·과장을 심각도와 함께 적발
- **연결 스킬**: jc-redteam(3축 감수: 내용·오탈자·대안)
- **입력 계약**: **완성된** 산출물만(진행 중 계획은 검증 대상 아님 — jc-redteam 정본 경계)
- **출력 계약**: 감수 리포트(Critical/Major/Minor) 또는 인라인 비평
- **페어링 주의**: 항상 **최하류** 배치. 고부담 산출물 팀에는 기본 포함 권장. 감수 결과 반영 턴을 팀 일정에 미리 확보

---

## 조합 원칙

1. **최소 구성** — 복합성 기준을 충족해도 필요 아키타입만. 8개 전부 투입은 예외이지 기본이 아니다(토큰·시간 오버헤드)
2. **병렬 후보 우선 식별** — 리서치·데이터분석처럼 독립 입력 아키타입을 먼저 골라 병렬 구간을 설계
3. **검증 내장** — 대외 제출물·고부담 산출물이면 리스크 아키타입을 구성안에 기본 포함
4. **임시 아키타입** — 카탈로그 밖 역량은 구성안에 임시 정의로 명시하고, 2회 이상 반복 시 카탈로그 편입 제안
