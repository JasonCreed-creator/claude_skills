# 핸드오프 규약 — 정본

에이전트 사이를 흐르는 것은 대화가 아니라 **파일**이다. 본 규약은 그 흐름의 계약을 정의한다. 환경별 세부는 각 킥오프 템플릿이 상속한다.

## 1. 입력 명시 의무

- 모든 에이전트 호출·역할 전환 시 **읽어야 할 파일 경로를 열거**한다. 컨텍스트 격리 환경(Code)에서는 생략 = 정보 누락 확정이고, 비격리 환경(Chat)에서도 명시가 승계 오류를 막는다
- 금지 표현: "앞 단계를 참고해", "위에서 한 대로", "맥락 알지?"

## 2. 출력 계약

- 산출 **경로·파일명·형식**을 호출 전에 계약하고, 에이전트는 계약된 위치에만 쓴다
- 파일명 규칙 권장: `<NN>-<에이전트slug>-<산출요지>.<ext>` (예: `01-strategy-outline.md`) — 순번이 의존성 체인을 가시화한다

## 3. 의존성 체인 판정

| 판정 | 기준 | 실행 |
|------|------|------|
| 순차 | 선행 산출이 후행의 입력 | 선행 완료 신호 후 착수 |
| 병렬 | 입력이 상호 독립 | 동시 진행 가능 — 판정 근거 1줄을 구성안에 기록 |
| 라운드 | 상호 반영 필요 | 전원 산출 → 메인 취합 → 수정 지시 일괄 배포 (실시간 협의 아님) |

- 확신이 없으면 순차로 판정한다. 잘못된 병렬의 비용(충돌·재작업)이 잘못된 순차의 비용(대기)보다 크다

## 4. 완료 신호

- 형식: `날짜 | 에이전트 | 산출 파일 | 상태(완료/부분/차단)` — PROGRESS.md 또는 킥오프에서 합의한 신호 파일에 1줄
- 신호 없는 작업은 미완료로 간주한다(크로스디바이스·크로스세션 동기의 유일한 근거)

## 5. ChainPayload/v1 접점

- **적용 대상**: 구조화 데이터의 스킬 간 핸드오프 — 견적(mice-estimate), KPI·실적(mice-dashboard), 회의 구조화(mice-meeting-minutes), 리서치 결과(mice-market-intel), 전략 캔버스(jc-strategy-canvas) 등
- **비적용**: 산문 문서·구성안·PI 텍스트 (봉투 없이 md/파일 직접 패스)
- 봉투 규약 정본: `jc-design-system`의 chaining-protocol — 본 스킬은 재정의하지 않고 참조만 한다

## 6. 쓰기 경계

- 킥오프 블록에 에이전트별 담당 경로를 **겹침 0**으로 선언한다. 공통 파일은 메인 전담
- 경계 변경은 킥오프 블록의 공식 개정 재제시로만 — 진행 중 암묵 확장 금지

## 7. 실패 핸드오프

- 계약 산출을 낼 수 없으면: **중단 보고**(사유 + 시도 내역 + 대안 1개) 후 메인 판정 대기. 조용한 스펙 축소·임의 대체 산출 금지
- 메인은 (a) 조건부 진행 (b) 해당 에이전트 재호출 (c) 구성안 개정 중 하나로 판정하고 구성안에 기록한다
