# Context Sources — 서피스별 맥락 수집 절차

브리프 '맥락 반영' 필드(주입 핵심 최대 3, 출처 명기)를 채우는 표준 절차. SKILL.md §3의 상세다.

## 1. Code 서피스

**소스 우선순위** (위에서 아래로, 있는 것만):

| 순위 | 소스 | 읽는 법 | 브리프에 기여하는 것 |
|------|------|---------|---------------------|
| 1 | `CLAUDE.md` | 프로젝트 지침 전문. SoT 포인터(`@경로` 참조)가 있으면 그 문서까지 따라간다 | 제약(운영 규칙·표기 규칙)·톤·산출물 표준 |
| 2 | `PROGRESS.md`(또는 동급 진행 문서) | 최신 상태 블록·에스컬레이션·직전 완료 항목 | 지시의 전후 맥락, 대기 중 의존성, 이미 결정된 사항 |
| 3 | 레포 실측 | 지시가 가리키는 파일·디렉터리를 Glob/Grep/Read로 직접 확인 | 산출물 스펙(기존 관례·구조), 가정 검증 |

**절차**: ① CLAUDE.md → SoT 문서 순으로 읽는다(이미 읽었으면 재독 생략) ② PROGRESS.md에서 지시와 교차하는 항목만 발췌 ③ 지시가 특정 파일·기능을 언급하면 해당 실물을 열어 확인한다 — 기억·추정으로 채우지 않는다(추측 금지).

## 2. Cowork 서피스

**소스 우선순위**:

| 순위 | 소스 | 읽는 법 | 브리프에 기여하는 것 |
|------|------|---------|---------------------|
| 1 | 작업폴더 `_INDEX.md` | 폴더의 한눈 요약(상태·핵심정보). 행사 폴더 표준이라면 가장 먼저 읽도록 설계된 파일 | 목표 재진술의 배경, 상태 제약 |
| 2 | 폴더 위계·표준 구조 | 하위 폴더 구성(brief/strategy/proposal/estimate/ops/outputs 등)으로 작업 단계를 파악 | 산출물이 놓일 위치, 매핑 스킬 힌트 |
| 3 | 최근 수정 파일 | 수정일 역순 상위 몇 개 — 직전 작업 흐름 | 지시의 직전 맥락, 중복 작업 방지 |

**절차**: ① `_INDEX.md`가 있으면 그것부터 — 없으면 폴더 루트의 README·개요 문서 ② 지시가 가리키는 하위 폴더만 연다(전체 폴더 스캔 금지 — 과적재의 시작) ③ 지시 관련 실물 파일 확인.

## 3. 상위 3 선별 기준 (과적재 금지의 실행)

수집한 맥락 후보 중 **브리프에 주입하는 것은 3개까지**. 아래 기준의 위에서부터 채운다:

1. **지시의 대상을 직접 규정하는 것** — 이 맥락이 없으면 산출물이 다른 물건이 되는 정보 (예: "제안서 만들어줘"에서 RFP의 평가 기준)
2. **산출물 스펙을 바꾸는 것** — 형태·분량·포맷·독자를 결정하는 정보 (예: 발주처 송부용이라는 사실 → 톤 분기)
3. **충돌·제약을 만드는 것** — 지키지 않으면 재작업이 되는 규칙·대기 의존성 (예: 진행 문서의 "Phase 4 완료 후 착수" 조건)

**버리는 것**: 배경 지식(알면 좋지만 산출물이 안 바뀌는 것), 오래된 이력, 지시와 평행한 다른 작업의 상태. 4개째 후보가 1~3번 기준을 만족하면 기존 3개 중 가장 약한 것과 교체한다 — 개수 상한이 우선한다.

**예외 — 금지·조건 조항은 상한 밖**: 소스에서 발견한 작업 금지·조건화 조항(예: "파일 변경 전 백업 선행 필수", "GO 승인 후 착수")은 맥락 3개와 경쟁시키지 않는다 — **'제약' 필드로 직행**한다. 3개 상한은 '맥락 반영' 필드에만 적용되는 규칙이다. 실측 교훈: 원인 분석에 유리한 재료를 맥락으로 뽑느라 같은 문서의 거버넌스 조항을 떨어뜨리면, 브리프가 실행 불가능하거나 위험한 산출 형태를 확정해 버린다. *(이 예외는 프로토콜 원문(SKILL.md §4)의 확장분이다 — §8 재증류 시 원문 반영 검토.)*

## 4. 출처 명기 형식

맥락 반영 필드의 각 항목에는 출처를 괄호로 병기한다:

```
맥락 반영: ① 평가 배점의 60%가 운영 역량 (출처: 00_brief/RFP.pdf §4)
          ② 제출 기한 7/15, 내부 검토 7/12 선행 (출처: PROGRESS.md 2026-07-01 항목)
          ③ 발주처 송부용 — 외부 톤 분기 적용 (출처: _INDEX.md 상태 블록)
```

- 파일은 `경로 §섹션` 또는 `경로 L줄`, 진행 문서는 `문서명 날짜 항목`, 대화는 `사용자 발언(금일)`.
- 출처를 못 대는 맥락은 맥락이 아니라 **가정**이다 — '가정' 필드로 옮긴다.

## 5. 소스가 비어 있을 때

- CLAUDE.md·PROGRESS.md·`_INDEX.md`가 없는 환경이면 그 사실 자체를 가정 필드에 남긴다: "A1) 프로젝트 지침 문서 부재 — 일반 관례로 진행".
- 맥락 0개로도 브리프는 성립한다(6필드 중 '맥락 반영'만 "해당 없음"). 브리프 생략의 사유가 되지 않는다.
