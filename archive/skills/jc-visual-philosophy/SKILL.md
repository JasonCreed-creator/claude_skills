# JC Visual Philosophy

**디자인 철학(미학 선언)을 세우고 → 그것을 단일 캔버스(.pdf/.png) 위에 비주얼 아트로 표현한다.** 원본 프리셋 `canvas-design`의 생성 철학·뮤지엄 퀄리티·크래프트맨십을 그대로 계승하되, jc-design-system의 **홈베이스 원칙**으로 길들인 버전이다.

> 원본은 "예술적 자유 = silent default"였다. jc 생태계에서는 그 전제를 뒤집는다 — **기본값은 jc 시그니처 한 가족**(네이비·일렉트릭 블루·인포그래픽 스케일 + Pretendard)이고, **임의 팔레트·디스플레이 폰트의 무한 자유는 이름 붙은 옵션('자유 아트 모드')으로만** 연다(플레이북 §4). 행사 키비주얼 한 장도 기획자님의 다른 산출물(제안서·대시보드·랜딩)과 같은 비주얼 언어를 쓰게 하기 위함이다.

## 무엇을 만드는가 / 무엇이 아닌가

- **만든다**: 미학 선언(.md) + 그것을 표현한 **단일 정적 아트오브젝트**(.pdf 또는 .png). 행사 키비주얼, 데크 표지 아트, 무드보드, 컨퍼런스 그래픽 컨셉.
- **아니다**: 토큰/팔레트 정의·오버레이(→ jc-design-system / jc-theme-factory), p5.js 등 코드 제너러티브 아트(→ jc-generative-art), 여러 장 슬라이드로 구성된 비딩/스폰서 데크(→ mice-proposal / mice-sponsor-deck). 본 스킬은 *움직이지 않는 한 장의 작품*이 본령이다(여러 장은 §멀티페이지 옵션의 아트북 형태로만).

## 두 단계 워크플로우

원본과 동일한 2박자다: **(1) 디자인 철학 생성(.md) → (2) 캔버스 표현(.pdf/.png).** 단 시작 전에 **모드 결정** 한 박자를 더 둔다.

### STEP 0 — 모드 결정 (홈베이스 vs 자유 아트)

산출 전에 반드시 어떤 모드인지 확정한다. **미지정 = 홈베이스(jc 기본)**.

| 모드 | 트리거 | 팔레트 | 타이포 | 브랜딩 크롬 |
|------|--------|--------|--------|------------|
| **홈베이스 (기본)** | 별도 지시 없음 | **jc 토큰**(시그니처 + §1.8 scale-blue/green/red/amber) | **Pretendard**(+ 모노 필요 시 JetBrains Mono) | jc 룩과 한 가족 |
| **자유 아트 (opt-in)** | 사용자가 "자유 아트 모드"·"free art"·"팔레트 자유"·"폰트 자유"를 **명시** | 임의 팔레트 허용 | canvas-fonts 디스플레이 폰트 허용 | 미학 우선, jc 종속 없음 |

- 모드 토글·각 모드의 정확한 색/폰트 규칙: **[`references/mode-toggle.md`](references/mode-toggle.md)** 가 정본.
- 애매하면 홈베이스로 가고, 한 줄로 사용자에게 알린다("jc 기본 룩으로 갑니다 — 임의 팔레트·디스플레이 폰트가 필요하면 '자유 아트 모드'라고 해주세요"). 자유 모드를 **추측으로 켜지 않는다.**

### STEP 1 — 디자인 철학 생성 (.md)

**레이아웃·템플릿이 아니라 비주얼 철학(미학 운동)을 쓴다.** 형태·공간·색·구도·이미지·패턴으로 해석될 세계관이다. 텍스트는 비주얼 액센트로만 존재한다.

1. **운동의 이름**(1~2단어): "Brutalist Joy" / "Chromatic Silence" / "Metabolist Dreams" 류.
2. **철학 서술**(4~6단락, 간결하되 완결): 공간과 형태 / 색과 재질 / 스케일과 리듬 / 구도와 균형 / 시각적 위계 — 각 측면을 한 번씩만 다루고 중복하지 않는다.
3. **크래프트맨십을 반복 강조**: 최종 작품이 "수많은 시간을 들여", "최고 수준의 전문가가 painstaking attention으로 다듬은", "master-level execution"처럼 보여야 함을 여러 번 못 박는다. 이 프레이밍이 핵심이다.
4. **창작 여지 남기기**: 미학 방향은 구체적이되, 다음 단계(캔버스)에서 해석할 공간을 남길 만큼 간결하게.

> 철학 자체는 **의도를 적시하지 않고 범용으로**(아무 데나 쓸 수 있는 미학 선언처럼) 쓴다 — 원본 원칙 유지. 작성 패턴·예시(Concrete Poetry / Chromatic Language / Analog Meditation 등)와 jc 토큰을 미학 어휘로 녹이는 법은 **[`references/philosophy-craft.md`](references/philosophy-craft.md)**.

산출: 철학을 **.md 파일**로 저장.

### STEP 1.5 — 미묘한 레퍼런스 추론 (THE SOUL)

캔버스를 만들기 전, 사용자 요청에서 **미묘하고 니치한 개념의 실(thread)**을 뽑아낸다. 주제는 **작품 안에 은밀히 박힌 레퍼런스** — 그 주제를 아는 사람은 직관적으로 느끼고, 모르는 사람은 그저 마스터급 추상 구성을 경험한다. 재즈 뮤지션이 다른 곡을 인용하듯, 아는 이만 알아챈다.

- 철학은 미학 *언어*를, 추론된 주제는 *영혼*(형태·색·구도에 보이지 않게 짜인 개념적 DNA)을 제공한다.
- 레퍼런스가 스스로를 announce하지 않도록 정제한다. MICE 맥락이면 — 행사 주제·산업·도시·브랜드 모티프를 **직접 로고/이름으로 박지 말고** 형태·리듬·색 온도로 암시한다. 회사·개인 식별정보는 절대 넣지 않는다(`#RULE-NO-COMPANY`).

### STEP 2 — 캔버스 표현 (.pdf/.png)

철학과 개념 프레임을 손에 쥐고, **단일 페이지의 고밀도·비주얼 우선 작품**을 만든다(요청 없으면 1페이지).

- 반복 패턴·완벽한 도형을 활용. 추상 철학을 *상상 속 학문의 과학 도감*처럼 다룬다 — 조밀한 마크의 축적, 반복 요소, 레이어드 패턴이 인내심 있는 반복으로 의미를 쌓고 지속적 응시에 보답한다.
- 희소하고 임상적인 타이포 + 체계적 레퍼런스 마커(상상 속 분류 체계의 다이어그램처럼)를 더한다. 단순한 문구/디테일을 미묘하게 배치해 앵커링한다.
- **모드별 색·폰트 규칙을 지킨다**(STEP 0). 홈베이스면 jc 토큰의 *제한된·의도적·응집된* 팔레트 — 임의 색을 더하지 않는다. 자유 모드면 canvas-fonts와 임의 팔레트 해방.
- 텍스트는 항상 미니멀·비주얼 우선이되 맥락이 속삭임(라벨)인지 강한 타이포 제스처인지 결정한다. **어떤 스케일이든: 페이지 밖으로 나가지 않고, 겹치지 않으며, 모든 요소가 캔버스 경계 안에서 여백을 갖는다 — 협상 불가.**
- 타이포를 아트의 일부로(추상이면 폰트를 캔버스 위로 끌어들여 — 디지털 식자만 하지 말 것).

캔버스 제작의 **렌더 파이프라인·폰트 적용·인쇄 라이트·세이프티 체크**는 **[`references/canvas-build.md`](references/canvas-build.md)** 가 정본. 산출: **단일 .pdf 또는 .png** + STEP 1의 철학 .md.

> **영화/게임/책 소재라도** 접근은 sophisticated. 만화풍·아마추어로 떨어지지 않는다 — 이것은 아트다.

### FINAL — 뮤지엄 패스 (정제, 추가 아님)

사용자는 이미 말했다: *"It isn't perfect enough. It must be pristine, a masterpiece of craftsmanship, as if it were about to be displayed in a museum."*

- **그래픽을 더하지 말고** 이미 있는 것을 극도로 crisp하게 정제한다. 새 함수를 부르거나 새 도형을 그리고 싶으면 STOP하고 물어라: "이미 여기 있는 걸 어떻게 더 아트로 만들까?"
- 구도·간격·색·타이포 — 모든 디테일이 전문가 수준의 크래프트맨십을 외치도록. 겹침 0, 포맷 결함 0을 재확인한다.
- 두 번째 패스를 돌려 코드로 돌아가 더 다듬는다.

### 멀티페이지 옵션 (요청 시에만)

추가 페이지는 같은 철학 선상이되 distinctly different하게. 첫 장을 *커피테이블 북의 한 장*으로 보고, 다음 장들은 원본의 유니크한 변주·기억으로 — 품격 있게 이야기를 잇는다. 한 .pdf로 묶거나 여러 .png로. (모드 규칙은 페이지마다 동일하게 유지 — 홈베이스 북은 끝까지 jc 팔레트.)

## AI스러운 기본값 회피 · 카피는 디자인 재료

STEP 1(철학)에서 STEP 2(캔버스)로 넘어가기 전, 두 가지를 스스로 검문한다.

- **AI 기본값 회피 체크**: 크림 배경+세리프+테라코타 액센트, 다크 배경+네온 글로우, 헤어라인 괘선의 브로드시트 레이아웃 — AI 생성물에서 어떤 브리프에나 반복되는 진부한 조합이다. 철학이 이 중 하나로 수렴했다면 우연한 선택이 아니라 기본값에 끌려간 것이니 되돌아가 다시 쓴다(자유 아트 모드에서 특히 경계).
- **과감함의 집중**: 모든 요소를 조금씩 특이하게 만들면 아무것도 특징이 되지 않는다. 브리프에서 가장 특징적인 요소 **하나**를 골라 거기에 과감함을 몰아주고, 나머지는 절제로 받친다.
- **카피는 디자인 재료**: 제목·라벨·캡션 문구는 타이포·여백과 동등한 디자인 구성 요소다. STEP 1 철학 단계에서 어휘의 톤(속삭임인가 선언인가)까지 함께 설계하고, STEP 2에서 자리만 채우는 placeholder 문구를 넣지 않는다. 기획자님의 행사 브리프 언어가 곧 재료다.

## SoT 앵커링 (값 미러링 금지)

홈베이스 모드의 색·폰트 **값을 본문/코드에 박지 않는다.** 빌드 시 jc-design-system에서 읽는다(플레이북 §3):

- 토큰 값: `jc-design-system/references/signature-tokens.md` §1 컬러·**§1.8 인포그래픽 스케일**·§2 폰트. 기계 파싱은 §6 JSON.
- 구현 헬퍼: `jc-design-system/scripts/jc_tokens.py`의 `load_tokens(sot_dir)` / `color(tok, key)`. 형제 경로로 SoT 탐색: `Path(__file__).resolve().parents[2] / "jc-design-system"`.
- 인쇄·라이트: `jc-design-system/references/mode-mapping.md`(§4.2 인쇄 라이트 강제, §9 WCAG 계산).
- 자유 아트 모드는 SoT 토큰에 묶이지 않으므로 미러 규칙 대상이 아니다(임의 색 허용). 단 폰트 파일 출처는 `references/fonts-strategy.md`.

## 공통 룰 (값 재정의 금지 · 정본 위임)

근거·전체 정의는 `jc-design-system/references/shared-rules.md#<RULE-ID>`로 위임한다.

- **`#RULE-NO-COMPANY`** — 작품·철학·파일명에 회사명·실명·부서·로고를 하드코딩하지 않는다. MICE 행사 모티프는 형태·색으로 암시만. 식별정보가 필요하면 외부 주입 변수(`{{client_company}}`·`{{personal_brand}}` 등)로.
- **`#RULE-WCAG`** — 작품 안에 **읽혀야 하는 텍스트**(제목·라벨)가 있으면 배경 대비 본문 4.5:1↑(큰 텍스트 3:1). 순수 장식 마크는 예외지만 가독 텍스트는 지킨다. 계산 표준 `mode-mapping.md §9`.
- **`#RULE-PRINT-LIGHT`** (권장) — MICE 배포물(키비주얼·표지)은 **인쇄 라이트 권장**: 라이트 배경 + jc 토큰. 다크 풀블리드 아트가 의도라면 그 자체가 디자인이므로 예외지만, 인쇄 배포가 목적이면 라이트로 간다.

## 생태계 연결 (재발명 금지)

- **검증**: 완성 아트오브젝트의 카피(라벨 오탈자)·대비·일관성 최종 점검은 **`jc-redteam`**(플레이북 §6). 원본의 "fresh Claude로 테스트" 자리에 jc-redteam을 끼운다.
- **테마 짝**: 산출물에 *기존 오버레이/클라이언트 톤*을 입히는 건 `jc-theme-factory`. 본 스킬은 미학 무드의 아트오브젝트, theme-factory는 토큰/오버레이 적용 — 경계 명확.
- **데이터 입력**: 다른 mice-* 산출 JSON을 모티프 소스로 받을 때는 `ChainPayload/v1` 봉투(`jc-design-system/references/chaining-protocol.md`). 데이터는 모티프로만 쓰고 식별정보는 배제.
